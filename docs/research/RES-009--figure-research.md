# RES-009 · 설명 그림 연구 종합(2026-11-18~24 완료)

- 질문: 어떤 그림이 글보다 잘 설명하는가, 모델이 그것을 빠르고 안정적으로 그리게 하려면 어떤 구조가 필요한가.
- 상세 출처·회차별 수치는 git 기록(이 파일 이전 판, RES-010~012)에 있다.

## 연구 방법

- 문헌: 학술(배치 선계획·구조 사상·멀티미디어 학습)과 실무(프롬프트 가이드·SVG 생성 경험담)를 교차 확인해, 양쪽이 지지하고 실측 실패를 설명하는 원칙만 남겼다(파레토 선별).
- 실측: 같은 글(dc08d3c0)의 자리를 고정하고 변수 하나만 바꿔 연구소(`mise run lab:run`, LAB-001)에서 생성했다. 사람이 변형 이름을 가린 채 판정했다(JUDGE-001).
- 반복: 정책 → 단계 설계 → 시간 → 스타일 → 움직임 순으로 한 번에 하나씩 고쳤다.

## 고찰: 무엇이 효과가 있었고 왜인가

- 필요성: 앵커 문장만으로 다시 알아내기 어려운 관계가 있을 때만 그림이 이긴다. 문장이 이미 말한 순서를 그리면 꾸밈이 된다(Larkin & Simon, Ainsworth).
- 구조 대응: 겉모습이 아니라 관계 구조가 같은 대상을 골라야 읽힌다. 요소 → 개념 대응표로 확인하면 장식과 떨어진 라벨이 함께 사라진다(Gentner, Mayer).
- 단계 분리: 후보 전체를 한 번에 정할 때는 비유 정책이 실행되지 않았다. 고른 자리만 다루는 구성 단계를 따로 두자 관계와 실패 조건까지 옮겼다. 원인은 문구가 아니라 단계 설계였다.
- 도구가 문장보다 강하다: "부분만 고쳐라" 같은 지시는 무시됐고, 배치 점검 도구·키트 서명 목록·원본 인계 같은 구조가 시간과 품질을 바꿨다. 시간은 출력 토큰에 비례한다(장당 15분 → 중앙값 6.6분).
- 스타일은 글 하나에 하나: 스타일 규칙이 공통 계약보다 앞서야 서로 구분됐고, 글자 양은 장면 범위(관계 하나·글자 10개 이하)가 정했다.
- 움직임: 원인 → 결과를 단계마다 하나씩 순서대로 나타낼 때 가장 잘 읽혔다. 강조를 옮기거나 전후만 바꾸면 무엇이 바뀌었는지 모른다. 고정 장면이 사라지는 빈 프레임은 읽기를 끊는다.

## 현재 선택

- 흐름: 위치 제안 → 구성(자리별 장면·대응표·스타일) → 사람 확인 → 한 층 생성 → 사람 확인(ADR-0026, ADR-0022).
- 스타일: anatomy·sketchnote·tablet·stick·manual 중 구성이 글 하나에 하나(ADR-0027).
- 움직임: 한 주기 @keyframes 순차 재현, 완료 상태가 기본(ADR-0028).
- 남은 한계: 5분 이내 생성은 일부만 달성, "하나라도 빠지면 실패" 같은 결여 관계는 아직 추상 부품으로 남는다.
