# RES-006 · 실제 편집 협업 방식 · 조사

- 기준일: 2026-11-11 · 관심사: 사람 피드백 해석·편집 수준·합격 기준 · 반영 ADR-0008
- 확인 수준: 업계 단체 정의(EFA)·편집자 실무 글 · 뉴스룸은 2차 자료라 예시로만 사용

## 관찰

| 실무 | 내용 | 출처 |
| --- | --- | --- |
| 편집 수준 | 구조(developmental: 내용·구성·장르) → 문장(line: 문단·문장) → 교열(copy) → 교정 순서 · 큰 문제를 먼저 해결한 뒤 문장 편집 | [EFA 정의](https://www.the-efa.org/editorial-services-definitions/) |
| 편집 메모 | 편집자가 작가에게 전체 문제와 **이유**를 쓰는 문서 · 비판마다 독자에게 무엇이 좋은지로 정당화 · 핵심 질문은 "의도대로 독자 문제를 푸는가" | [Bernoff: edit memo](https://bernoff.com/blog/what-is-a-developmental-editors-edit-memo-and-why-is-it-essential) |
| 살릴 것 명시 | 문제만 나열하면 수정하면서 장점까지 지워짐 · 잘 된 점을 함께 적음 | [Editfast: 편집 서신 읽기](https://editfast.com/faq/books/reading-an-editorial-letter/) |
| 우선순위 | 범위·독자·논지 같은 결정적 문제와 다듬기를 분리 · 순위 매긴 짧은 목록 | 같은 자료군 |
| 분량 결정 | 뉴스룸은 지면 배정(budget)에서 길이를 먼저 정하고 데스크가 맞춤 · 대량 축소는 문장 다듬기가 아닌 배정 문제 | [Newsroom](https://en.wikipedia.org/wiki/Newsroom) (2차) |

## AIN 함의

- 사람의 모호한 피드백("너무 길어")은 바로 작업 지시가 아니라 **편집 메모로 번역**해야 함 · 원래 요구·검토 결과·측정값과 함께 해석
- 편집 수준이 복귀 범위를 정함 · 구조 편집(분량 20% 이상 변화 포함)은 구성부터, 문장·교열은 초고부터
- 메모는 의도·우선순위·살릴 것·합격 기준·가정 · 근거 없는 해석은 가정으로 드러내 사람이 바로잡음
- 합격 판정은 메모 기준으로: 수치는 코드(ADR-0007), 나머지는 검토 판정(데스크 체크)
