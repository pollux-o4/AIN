# RES-006 · 실제 편집 협업 방식 조사

- 기준일은 2026-11-11이다. 이 문서는 사람 피드백 해석, 편집 수준, 합격 기준을 조사한 결과이며, ADR-0008에 반영하였다.
- 확인 수준은 업계 단체 정의(EFA)와 편집자 실무 글이다. 뉴스룸 자료는 2차 자료이므로 예시로만 사용한다.

## 관찰

| 실무 | 내용 | 출처 |
| --- | --- | --- |
| 편집 수준 | 구조(developmental: 내용·구성·장르) → 문장(line: 문단·문장) → 교열(copy) → 교정 순으로 진행하며, 큰 문제를 먼저 해결한 뒤 문장을 편집한다. | [EFA 정의](https://www.the-efa.org/editorial-services-definitions/) |
| 편집 메모 | 편집자가 작가에게 전체 문제와 **이유**를 적어 주는 문서로, 비판마다 독자에게 어떤 점이 좋은지로 근거를 댄다. 핵심 질문은 "의도대로 독자 문제를 푸는가"이다. | [Bernoff: edit memo](https://bernoff.com/blog/what-is-a-developmental-editors-edit-memo-and-why-is-it-essential) |
| 유지할 요소 명시 | 문제만 나열하면 수정 과정에서 장점까지 지워지므로 잘된 점을 함께 적는다. | [Editfast: 편집 서신 읽기](https://editfast.com/faq/books/reading-an-editorial-letter/) |
| 우선순위 | 범위, 독자, 논지 같은 결정적 문제와 다듬기를 분리하여 순위를 매긴 짧은 목록으로 작성한다. | 같은 자료군 |

## AIN 함의

- 사람의 모호한 피드백("너무 길어")은 바로 작업 지시로 쓰지 않고 **수정 해석**으로 정리해야 한다. 원래 요구와 검토 결과, 측정값을 함께 보고 해석한다.
- 편집 수준이 복귀 범위를 정한다. 구조 편집(분량 20% 이상 변화 포함)은 구성 단계부터, 문장·교열 편집은 초고 단계부터 다시 작성한다.
- 수정 해석은 의도, 우선순위, 유지할 요소, 합격 기준, 가정으로 구성하며, 근거 없는 해석은 가정으로 드러내 사람이 바로잡게 한다.
- 합격 판정은 수정 해석을 기준으로 내린다. 수치는 코드(ADR-0007)가 확인하고, 나머지는 검토 판정이 맡는다.
