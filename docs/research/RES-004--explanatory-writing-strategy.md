# RES-004 · 설명 글 설계 전략

- 이 문서는 원칙(RES-002)과 사례(RES-003)에서 도출한 도구 독립적 글 설계 절차와 장르 경계를 다룬다.
- 변경 이유는 작성 방법론 수정이며, AIN 구현과는 무관하다.

## 인과 모델

```text
작업기억은 작다 (Kalyuga 2003)
 → 먼저 전체 개요를 제시한다 (요약·핵심 표)          P2
 → 독자 수준에 맞춰 경로를 나눈다 (배지·접기)          P1
 → 한 번에 하나씩, 같은 비유를 유지한다 (일관 비유)    P3·P4
 → 오해가 생길 지점을 직접 반박한다                   P5
 → 마지막에 독자가 스스로 인출하게 한다               P6
 → 실제 독자의 혼동을 반영하여 수정한다 (보정 로그)    반복
```

## 글 설계 절차

- 적용 대상은 설명(explain) 구간이다.

1. 범위 설정: 독자가 이 글을 읽고 할 수 있게 될 일 1가지를 정하고, 그 일에 필요 없는 내용은 제외한다(정처기 감자 사례의 최소 범위 전략).
2. 독자 카드 작성: 독자의 수준, 이미 아는 것, 모르는 용어, 흔한 오해, 이름이 같은 다른 개념을 정리한다.
3. 단일 비유 체계 구성: 대응표(비유 요소 ↔ 개념 요소)와 비유가 맞지 않는 지점을 정리한다.
4. 의존 순서 정렬: 개념을 의존 순서로 정렬한 뒤 구간별 수준을 표시하고, 선택 구간(호기심)과 접힌 질문을 분리한다.
5. 구간 카드 작성: 핵심 원칙 1문장, 구체물, 따라가는 예제, 반박할 오해, 확인 질문을 작성한다.
6. 초고 작성: 정의 → 비유 → 이유 순으로 전개한다. 캡션과 소제목은 결론 문장으로 쓰고, 전문어는 첫 등장 시 풀이하며 한 대상에는 한 이름만 쓴다.
7. 검토: 측정(코드)과 판단(AI)을 분리하고, 독자가 자기 말로 다시 말할 수 있는지(paraphrase)를 확인한다.
8. 보정: 사용자 피드백을 혼동 지점 단위로 기록한 뒤 해당 구간만 다시 쓴다.

## 장르별 경계

| mode | 가져올 것 | 가져오지 않을 것 |
| --- | --- | --- |
| explain | 글 설계 절차 전체를 적용한다. | — |
| procedure | 전체 개요 우선 제시, 한 단계 한 행동, 함정 경고, 확인 방법을 적용한다. | 비유 체계와 캐릭터는 제외한다. |
| argue | 결론 우선 제시, 근거 묶음, 반론 예상(P5 응용)을 적용한다. | 수준 배지와 연습 문제는 제외한다. |
| narrate | 구체 장면, 군더더기 제거, 목소리 보존을 적용한다. | 정의→비유→이유 틀과 표는 제외한다. |

- 숙련 독자(readerLevel 높음) 대상 글에서는 McNamara 1996에 따라 풀이 밀도를 낮추고 추론 여지를 남긴다.
- 정처기 감자 사례의 시험 전용 장치(출제 배지, 정답 인정 범위)는 "독자 동기 표시"와 "확인 질문" 원칙으로만 반영한다.
