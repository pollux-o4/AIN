# RES-004 · 설명 글 설계 전략

- 관심사: 원칙(RES-002)과 사례(RES-003)에서 도출한 도구 독립적 글 설계 절차 · 장르 경계
- 변경 이유: 작성 방법론 수정 · AIN 구현과 무관

## 인과 모델

```text
작업기억은 작다 (Kalyuga 2003)
 → 먼저 지도를 준다 (요약·핵심 표)              P2
 → 독자 수준에 맞춰 길을 나눈다 (배지·접기)       P1
 → 한 번에 하나, 같은 비유 위에서 (일관 비유)    P3·P4
 → 오해가 생길 자리를 직접 반박한다             P5
 → 마지막에 스스로 꺼내 보게 한다               P6
 → 실제 독자 혼동을 받아 다시 고친다 (보정 로그)  반복
```

## 글 설계 절차

- 적용: 설명(explain) 구간

1. 범위: 독자가 이 글로 할 수 있게 될 일 1개 · 그 일에 필요 없는 내용 제외(감자의 최소 범위 전략)
2. 독자 카드: 수준 · 이미 아는 것 · 모르는 용어 · 흔한 오해 · 이름이 같은 다른 개념
3. 비유 체계 1개: 대응표(비유 요소 ↔ 개념 요소) · 맞지 않는 지점
4. 개념을 의존 순서로 정렬 → 구간별 수준 표시 · 선택 구간(호기심)·접힌 질문 분리
5. 구간 설계 카드: 핵심 1문장 · 구체물 · 따라가는 예제 · 반박할 오해 · 확인 질문
6. 초고: 정의 → 비유 → 이유 · 캡션·소제목은 결론 문장 · 전문어 첫 등장 풀이 · 1대상 1이름
7. 검토: 측정(코드)과 판단(AI)을 분리 · 독자가 자기 말로 다시 말할 수 있는지(paraphrase)
8. 보정: 사용자 피드백을 혼동 지점 단위로 기록 → 해당 구간만 재작성

## 장르별 경계

| mode | 가져올 것 | 가져오지 않을 것 |
| --- | --- | --- |
| explain | 글 설계 절차 전체 | — |
| procedure | 지도 먼저 · 한 단계 한 행동 · 함정 경고 · 확인 방법 | 비유 체계 · 캐릭터 |
| argue | 결론 먼저 · 근거 묶음 · 반론 예상(P5 응용) | 수준 배지 · 연습 문제 |
| narrate | 구체 장면 · 군더더기 제거 · 목소리 보존 | 정의→비유→이유 틀 · 표 |

- 숙련 독자(readerLevel 높음): McNamara 1996에 따라 풀이 밀도를 낮추고 추론 여지를 남김
- 감자의 시험 전용 장치(출제 배지·정답 인정 범위)는 "독자 동기 표시"·"확인 질문" 원칙으로만 이식
