# RES-011 · 그림 대상 정책 파일럿과 생성 시간 단축

- 질문: 문단에 비유가 없어도 현실 장면 비유(metaphor)가 문단 개념을 그대로 그리는 방식(baseline)보다 나은가? 그림 한 장을 얼마나 빨리 만들 수 있는가?
- 실행: `mise run lab:run`. Paseo 데몬과 n8n이 필요하고 앱 브리지는 꺼 둔다. 원문은 `.local/`에만 둔다. 실측은 모두 n=1~3이다.

## 판정 기준(고정)

- 사람이 변형 이름을 가린 채 예·아니요로 판정한다. 검토(LLM) 판정이 사람과 다르면 사람 판정을 따른다(JUDGE-001).
  1. 실재: 그림 속 장면을 현실의 사물·장소·행동 이름으로 부를 수 있다.
  2. 구조: 본문의 관계와, 그 관계가 깨지는 경우가 장면 안에 성립한다.
  3. 라벨 가림: 라벨을 가려도 관계가 읽힌다.
  4. 오개념 없음: 본문에 없는 추론을 부르지 않는다.
- 채택 조건: 대상 자리에서 생성 회차의 과반이 통과하고 baseline보다 통과 수가 많다. 대조군이 나빠지지 않는다. 장당 토큰은 baseline의 1.5배 이하이다. 채택한 뒤에도 다른 글 2편에서 다시 확인한다.

## 결론

| 주제 | 결과 | 근거 |
|---|---|---|
| 위치 제안에서 비유 정하기 | 실패(본문 밖 장면 0건) | 후보 16~18개를 한 번에 정하는 단계에서는 정책이 실행되지 않았다. 원인은 정책 문구가 아니라 단계 설계였다. |
| 구성 단계 분리(ADR-0026) | 성립. f13 명함 바구니, f14 지하철 노선, f15 구슬 실 | 고른 자리만 다루자 metaphor가 관계와 실패 조건까지 옮겼다. baseline은 비유 없이 남았다. 아직 n=1이어서 채택 조건은 판정하지 않았다. |
| 여러 유형으로 일반화 | 6장(gen6b) 모두 성공, 장당 7~9분 | 형태(작업대·막대·흐름·동전·톱니)가 달라도 같은 지시로 그렸다. |
| 국소 수정(`fix`) | 1회로 지적한 곳만 고침 | 구도·색·대비는 유지되었다. |

## 시간 단축 경과

| 단계 | 장당 시간 | 효과가 있었던 조치 |
|---|---|---|
| 3층, 한 장씩 | 15~17분 | — |
| 2층, 동시 생성 | 10.5~13.8분 | 원본 인계, 동시 생성, 브리지 메모리 수정 |
| 한 층 + 배치 점검 도구 | 7.5~8분 | 층 사이 인계·재확인 제거, 겹침을 좌표로 알림 |
| 5분 튜닝(fast1~6, 13장) | 4.5~8.7분, 중앙값 6.6분 | 키트 서명 목록, 글자 뺀 PNG 판정, 빈자리·viewBox 후보, 형태 절약 |

- 5분 이내는 13장 중 3장으로, 목표는 미달성이다. 품질은 지켰다. 모든 장이 글자 없이도 읽혔고 라벨은 13~24개로 줄었다.

## 교훈

- 시간은 출력 토큰에 비례한다(초당 약 175토큰). 대부분은 코드 작성이며, 렌더 횟수보다 한 번에 쓰는 양이 중요하다.
- 문장 지시는 지켜지지 않는다. "부분만 편집"과 "다시 쓰지 말 것" 모두 무시되었다. 도구와 구조가 효과를 냈다.
- 원인을 보지 않은 횟수 상한은 효과가 없었다. 세션 기록(`transcript_full.jsonl`)으로 낭비를 확인한 뒤 고친다.
- 동시 6장은 제공자 한도(`usage_limit`)를 빨리 소모한다. 장당 캐시 입력은 300만~400만 토큰이다.

## 남은 병목과 다음 지렛대(미실시)

- 첫 작성은 2.6만~3.5만 토큰, 약 2.5분이 든다. 장면 세부를 쓰는 기본 비용이다.
- 원본 전체 재작성이 장당 0~2회, 회당 약 1.5분 남아 있고, 시간 분산의 주원인이다. 다음 지렛대는 장면 값 파일과 그리기 파일을 나눠 구조로 막는 것이다.
- 인물·작업대처럼 반복되는 모티프를 구성 단계 뒤 한 번 만들어 모든 그림이 쓰게 한다. ADR-0022의 일관성과 같은 방향이다.
- f3(다섯 조건, "하나라도 빠지면 실패")은 두 변형 모두 조건 칸 추상 부품으로 남았다.
