# RES-009 · 설명 그림 생성 원칙: 연구·실무 조사

- 기준일은 2026-11-18이다. 시각자료 생성이 그림 한 장에 약 25분, 1천만 토큰, 330KB가 들고 요소를 모두 담는 문제를 계기로 조사하였다.
- 핵심 질문은 두 가지이다. 모델이 설명 그림을 잘 그리게 하는 작업 구조는 무엇인지, 그리고 비용을 줄이는 인계 방식은 무엇인지이다.
- 학술 출처 약 36건과 실무·매체·커뮤니티 출처 40건을 1차로 모아 각각 원칙 후보를 4~5개로 추렸다. 이 문서는 그 후보를 교차 확인해 남긴 원칙 5개를 다룬다. 적용 결정은 ADR-0024가 원본이다.

## 파레토 선별

- 1차 후보는 학술 4개, 실무 5개, 모두 9개이다. 같은 원칙을 다르게 표현한 것은 하나로 묶었다.
- 다음 두 조건을 모두 충족한 원칙을 남겼다.
  - 학술과 실무 양쪽에서 지지된다. 한쪽에서만 지지되면 근거가 강해야 한다.
  - 이번 실측 실패(330KB 파일, 모든 요소를 담은 그림, 좌표부터 정해 세 번 다시 그림, 층당 도구 호출 40회) 가운데 하나 이상을 설명한다.

### 남긴 원칙 5개

1. 그리기 전에 구성을 의미 수준에서 확정한다. 무엇을, 어떤 순서로, 어느 영역에 두고, 무엇이 움직이는지를 좌표 없이 정한다. (출처 1·2·8·9, 학술 12건·실무 14건)
2. 좌표와 형식은 코드가 맡는다. 모델에는 자유 좌표 대신 유형별 배치·슬롯·id 어휘를 준다. (출처 3·10, 학술 6건·실무 9건)
3. 그림 하나에 메시지 하나를 담는다. 메시지를 이루는 요소는 빠짐없이 넣고, 나머지는 덜어낸다. (출처 11, 실무 9건. 학술 근거는 약하다)
4. 출력은 작게 압축하고 수정은 부분 단위로 한다. 명세와 키프레임만 주고받고, 같은 입력은 다시 계산하지 않는다. (출처 4·5·6, 학술 6건·실무 7건)
5. 렌더를 보고 하는 검증은 횟수를 제한한다. 기하 오류는 코드가 고치고, 모션은 선언형으로 만들어 움직임 줄이기 설정을 존중한다. (출처 7·12, 학술 8건·실무 7건)

- 원칙 3의 단서는 자체 시험에서 얻었다. 덜어내기만 적용한 그림은 대비 축 하나만 남고 "기준이 분명하다"는 뜻이 사라졌다. 따라서 숫자 상한을 두지 않고 "메시지를 이루는 요소인가"로 판단한다.

### 제외한 후보

- 구성 명세를 그림마다 사람이 승인하는 방식: 실무 근거는 있다. 하지만 그림이 많으면 흐름이 막히고, 현재 확인 단계가 이미 있다. 선택 기능으로 둔다.
- 객체 수 상한: 한 사례에 맞춘 상한이 되어 원칙 3과 충돌한다.
- 솔버 도입: 흐름·비교·순환 유형은 배치 템플릿으로 충분하다고 추론하였다. 실측으로 확인해야 한다.
- "렌더·비평 최소 5회" 규칙: 근거가 없다.
- 영상 모델 전용 용어(카메라 이동, MCSLA)와 학습형 SVG 토크나이저, 확산 기반 SVG, TikZ 강화학습: 우리 파이프라인과 맞지 않는다.

## 측정 기준(비교용)

- 2026-11-18 운영 데이터, f1~f4의 12층(층 하나 = 초안·내용·시각 가운데 한 단계)이다.
  - 층 하나에 3~17분, 도구 호출 13~40회, 캐시 입력 160만~1,230만 토큰이 들었다.
  - SVG는 330~390KB이고, 그 가운데 84%가 path 좌표이다.
- `ain usage`가 이 12층을 "거부"로 표시하지만, 작업 기록상 모두 완료되어 채택되었다. 집계 오류이다.
- 파일럿(수동 작성 장면 + 결정적 렌더러, 합성 측정)은 같은 f4로 시험하였다. 장면 JSON 2.6~3.8KB에서 SVG 32~53KB가 30ms에 나왔다. 장면 작성에 드는 모델 비용은 측정하지 않았다.
