# OPS-003 · 애플리케이션·AI 실행 연결

- 기동: `mise run editorial:start`로 기동한다(OPS-001). runtime이 편집 모듈, SQLite, Paseo 실행 포트, n8n 전달 포트를 조립한다(ARCH-001).
- 직접 애플리케이션 실행: `mise run ai:bridge`로 직접 실행한다. 기존 브리지 포트 3230을 사용하며 기본 workflow가 인증된 advance를 호출한다.
- 설치·인증·세션: 공통 Paseo SDK·데몬을 사용하며 프로젝트에 CLI를 중복 설치하지 않는다.
- 제공자 확인: `mise run ai:providers`를 실행하여 공통 SDK에서 직접 조회한다. 정확한 기본 모델 조회, 로그인, 사용량은 제공자 정책을 따른다.
- 저장: `.local/ai-runtime/`에 SQLite, 작업, 자격증명을 저장하며 원문·AI 결과·비밀값은 로그에 기록하지 않는다.
- 원문·검토 문맥: 단계에 필요한 결과와 직전 수정 대상만 전달한다. 분량은 사용자 요구를 우선하며 검토 단계에는 실측 문자 수를 전달한다.
- 호출 제한: 기본 실행은 8회, 수정과 명시적 재개는 9회로 제한한다(같은 단계 안의 다음 구간 작성과 코드 검사가 거부한 결과의 다시 쓰기는 횟수에 포함하지 않으며, 도메인 상한과 전체 제한 시간이 초과를 막는다). 전체 제한 시간은 1,800초, 요청별 제한 시간은 300초로 두어 품질을 우선하고 사고 단계를 유지한다. 단순 재연결로 예산을 초기화하지 않으며, 자동 재시도와 대체 모델 전환은 하지 않는다.
- 실제 계약 검증: `mise run ai:test:contract`는 기본 모델 연결 확인 1회를 통과한 뒤 합성 글 1편(필수 8단계와 구간별 초고·다시 쓰기, 최대 30회·1,800초)을 실행한다. report.json의 `quality`에 코드 지표와 검토 판정을 기록하며, 별도의 브리지·n8n·SQLite·작업 폴더를 사용하고 운영 데이터는 사용하지 않는다.
- 연결만 검증: `mise run ai:pilot`은 최대 1회만 호출한다(요청 제한 90초, 새 세션 첫 호출 실측 38~49초). 따라서 전체 글 검증은 연결 확인을 포함하여 최대 31회가 된다.
- 실제 모델 실행 조건: 사람이 터미널에서 직접 실행하며, 그 밖의 실행은 `AIN_LIVE=1`이 없으면 거부한다. 또한 일반 검증에는 묶지 않는다(TIME-001).
- 반복 평가: `mise run ai:eval`은 기본적으로 글감 4종을 각 1회 실행하며, 멱등성 평가는 `-- --trials 3`으로 실행한다. 글감별로 같은 입력을 반복 실행하여 기준별 통과율(멱등성)과 호출·시간·토큰 분포를 `.local/eval-*/summary.json`에 기록하고, 모든 반복이 필수 기준을 통과하여야 성공으로 종료한다. 글감은 `paseo/live/cases`, 기준은 `paseo/live/grade`에 두며, 프롬프트나 모델을 변경하면 전후 결과를 표로 비교한다(ADR-0013).
- 실패 처리: 실패 시에는 해당 실행에 속한 n8n·HTTP·작업만 종료되었는지 확인한다. 중단 원인이 분명하지 않으면 실패로 보고하며 자동 재실행은 하지 않는다.
- 과거 실측: PILOT-001을 참조한다. 이전 원시 워크플로는 현재 실행 경로에서 제외하며 과거 비공개 증거는 보존한다.
- 기존 프로세스: 기존 프로세스가 이전 코드 또는 이전 protocol로 실행 중이면 진행 중인 작업을 확인한 뒤 `editorial:start`가 재시작한다(OPS-001).
- 범위 구분: 실제 게시, 웹 조사, 공개 서버 운영은 별도이며, 글 준비, 만족, 발행 준비 승인을 구분한다.
