# OPS-003 · 애플리케이션·AI 실행 연결

- 기동: `mise run editorial:start` (OPS-001) · runtime이 편집 모듈·SQLite·Paseo 실행 포트·n8n 전달 포트를 조립 · ARCH-001
- 직접 애플리케이션 실행: `mise run ai:bridge` · 기존 브리지 포트 3230 · 기본 workflow가 인증된 advance 호출
- 설치·인증·세션: 공통 Paseo SDK·데몬 · 프로젝트에 CLI 중복 설치 없음
- 제공자 확인: `mise run ai:providers` · 공통 SDK 직접 조회 · 정확한 기본 모델 발견·로그인·사용량은 제공자 정책
- 저장: `.local/ai-runtime/`의 SQLite·작업·자격증명 · 원문·AI 결과·비밀값은 로그에 기록하지 않음
- 원문·검토 문맥: 단계에 필요한 결과와 직전 수정 대상만 전달 · 분량은 사용자 요구 우선·검토에 실측 문자 수 전달
- 호출 제한: 기본 8회·수정/명시적 재개 9회(같은 단계 안의 다음 구간·코드 검사가 거부한 결과의 다시 쓰기는 횟수 밖, 도메인 상한과 전체 시간이 막음) · 전체 1,800초·요청 300초(품질 우선, 사고 단계 유지) · 단순 재연결 예산 초기화·자동 재시도·대체 모델 없음
- 실제 계약 검증: `mise run ai:test:contract` · 기본 모델 연결 확인 1회 통과 후 합성 글 1편(필수 8단계 + 구간별 초고·다시 쓰기, 최대 30회·1,800초) · report.json의 `quality`에 코드 지표·검토 판정 기록 · 별도 브리지·n8n·SQLite·작업 폴더 · 운영 데이터 사용 없음
- 연결만 검증: `mise run ai:pilot` · 최대 1회(요청 90초, 새 세션 첫 호출 실측 38~49초) · 전체 글 검증은 연결 확인 포함 최대 31회
- 실제 모델 실행 조건: 사람이 터미널에서 직접 · 그 밖의 실행은 `AIN_LIVE=1` 없이는 거부 · 검증에 묶지 않음 · TIME-001
- 반복 평가: `mise run ai:eval` 기본 글감 4종 × 1회 · 멱등성은 `-- --trials 3` · 글감별로 같은 입력을 반복 실행해 기준별 통과율(멱등성)과 호출·시간·토큰 분포를 `.local/eval-*/summary.json`에 기록 · 모든 반복이 필수 기준을 통과해야 성공 종료 · 글감 `paseo/live/cases` · 기준 `paseo/live/grade` · 프롬프트·모델을 바꾸면 전후를 이 표로 비교 · ADR-0013
- 실패: 자기 실행의 n8n·HTTP·작업만 종료 확인 · 불명확한 중단은 실패로 보고 · 자동 재실행 없음
- 과거 실측: PILOT-001 · 이전 원시 워크플로는 현 실행 경로에서 제외 · 과거 비공개 증거는 보존
- 기존 프로세스: 이전 코드·protocol이면 진행 중 작업 확인 후 `editorial:start`가 재시작 · OPS-001
- 실제 게시·웹 조사·공개 서버는 별도 · 글 준비·만족·발행 준비 승인을 구분
