# OPS-003 · 애플리케이션·AI 실행 연결

- 기동: `mise run editorial:start`로 Go 서버를 시작한다(OPS-001). 서버는 SQLite, 편집 실행기, Paseo WebSocket 연결을 조립한다(ARCH-001).
- 공통 Paseo: 별도 공통 도구에서 제공자를 인증하고 데몬을 시작한다. `PASEO_HOME`을 지정하지 않으면 현재 공통 실행기의 `../paseo/home`을 사용한다. 이전 설정이 그곳에 없으면 `../paseo/.local/home`을 확인한다.
- 모델 설정: 기본 구성은 Antigravity Hydrogen Medium이며 검토·재작업은 High를 사용한다. 다른 모델과 사고 단계는 `AIN_PROVIDER`, `AIN_MODEL`, `AIN_THINKING`, `AIN_REVIEW_THINKING`으로 지정한다. `mise run ai:providers`로 제공자 가용성을 확인한다.
- 세션 정리: Go 서비스를 종료한 뒤 `mise run ai:prune`을 실행한다. `-- --all`은 유휴가 확인된 대기 세션까지 보관한다. 활성 작업과 상태가 불확실한 세션은 유지한다.
- 레거시 복구: `mise run ai:bridge`는 기존 Node 브리지 복구용이다. 검증된 별도 레거시 DB에만 연결한다(OPS-001, OPS-002).
- 저장: `.local/ai-runtime/`에 SQLite, 작업, 자격증명을 저장하며 원문·AI 결과·비밀값은 로그에 기록하지 않는다.
- 원문·검토 문맥: 단계에 필요한 결과와 직전 수정 대상만 전달한다. 분량은 사용자 요구를 우선하며 검토 단계에는 실측 문자 수를 전달한다.
- 호출 제한: 기본 실행은 8회, 수정과 명시적 재개는 9회로 제한한다(같은 단계 안의 다음 구간 작성과 코드 검사가 거부한 결과의 다시 쓰기는 횟수에 포함하지 않으며, 도메인 상한과 전체 제한 시간이 초과를 막는다). 전체 제한 시간은 1,800초, 요청별 제한 시간은 300초로 두어 품질을 우선하고 사고 단계를 유지한다. 단순 재연결로 예산을 초기화하지 않으며, 자동 재시도와 대체 모델 전환은 하지 않는다.
- 실제 계약 검증: `mise run ai:test:contract`는 연결 확인을 통과한 뒤 Go 편집 API로 합성 글을 작성한다. 별도 SQLite·작업 폴더를 사용한다. 기본 글 작성 한도는 30회이며, `CONTRACT_FEEDBACK`을 지정하면 수정 검증을 포함해 최대 60회이다. 글 한 편의 검증 제한 시간은 1,800초이다. 결과와 품질 판정은 비공개 `report.json`에 남긴다.
- 연결만 검증: `mise run ai:pilot`은 고정 응답의 Paseo 요청을 최대 1회 보낸다. 제한 시간은 90초이다. 공통 Paseo의 위치가 기본값과 다르면 `PASEO_HOME`을 지정한다.
- 실제 모델 실행 조건: 사람이 터미널에서 직접 실행하며, 그 밖의 실행은 `AIN_LIVE=1`이 없으면 거부한다. 또한 일반 검증에는 묶지 않는다(TIME-001).
- 반복 평가: `mise run ai:eval`은 기본적으로 글감 4종을 각 1회 실행하며, 멱등성 평가는 `-- --trials 3`으로 실행한다. 글감별로 같은 입력을 반복 실행하여 기준별 통과율(멱등성)과 호출·시간·토큰 분포를 `.local/eval-*/summary.json`에 기록하고, 모든 반복이 필수 기준을 통과하여야 성공으로 종료한다. 글감은 `paseo/live/cases`, 기준은 `paseo/live/grade`에 두며, 프롬프트나 모델을 변경하면 전후 결과를 표로 비교한다(ADR-0013).
- 실패 처리: 실패 시에는 이번 검증의 Go 실행기와 소유 세션만 정리한다. 정리 여부를 확인할 수 없으면 보고서에 남긴다. 중단 원인이 분명하지 않으면 실패로 보고하며 자동 재실행은 하지 않는다.
- 과거 실측: PILOT-001을 참조한다. 이전 원시 워크플로는 현재 실행 경로에서 제외하며 과거 비공개 증거는 보존한다.
- 기존 프로세스: 시작 명령은 자기 Go 프로세스의 소유권과 빌드 상태를 확인한다. 같은 데이터에 연결된 Node 작성자나 다른 서비스의 포트 점유를 발견하면 시작을 중지한다(OPS-001).
- 범위 구분: 실제 게시, 웹 조사, 공개 서버 운영은 별도이며, 글 준비, 만족, 발행 준비 승인을 구분한다.
