# 상태·문구 최종 검수 · `EDIT-002`

- 근거: 실제 상태 추적, 텍스트 최소화, 역할 없는 UI 제거 요청에 따른다.
- 선택: 단계만 표시, 추정 진척률, 상시 로그, '현재 상태·확인 시각·접힌 이력' 방식을 비교해 마지막 대안을 선택한다.
- 제외 근거: 단계 표시만으로는 연결 지연을 판단할 수 없고, AI 내부 진척률은 제공되지 않으며, 상시 로그는 본문 읽기를 방해한다.
- 상태 정본: 상태 정본은 `monitor.mjs`이며 대기, 관측 중, 확인 지연, 확인 필요, 중단, 실패, 초안 준비 상태를 구분한다.
- 확인 근거: 인증된 n8n worker 접속과 Paseo 작업 결과를 근거로 삼으며, 완료는 계약 검증을 통과한 결과를 받은 뒤에 표시한다. heartbeat를 AI 진척률로 해석하지 않는다.
- 기록: 요청, AI 요청·완료, 오류, 중단 확인, 재개 이력을 회차, 시각, 작업 ID, n8n 실행 ID와 함께 보존한다. 매 heartbeat마다 로그를 생성하지는 않는다.
- 지연 기준: 기준 값은 `STALE_AFTER_MS`이며, 서비스 상태 변경 시각과 worker 확인 시각을 분리한다. 연결이 끊기면 마지막 결과를 유지하고 변경 동작을 비활성화한다.
- 이력은 적용 이후의 관측부터 저장하며, 기존 글의 과거 시각과 단계를 소급 생성하지 않는다.
- 유지: 입력 이름, AI 전송, 원문 읽기 제약, 검토 의견의 불확실성, 실패 원인, 복구 행동은 남긴다.
- 제거: 중복 소개, 상시 저장 알림, 상시 진행 안내, 빈 검토 메시지, 입력 화면 새 글, 실행 없는 일반 n8n 링크는 없앤다.
- 검증: 새로고침 뒤에도 이력이 일치하는지, 실제 n8n 실행마다 링크가 맞는지, 확인 지연과 AI 실패를 구분하는지, 조회·재연결할 때 AI를 중복 생성하지 않는지, 네트워크가 끊겼을 때 진행 중으로 잘못 표시하지 않는지를 검증한다.
- 수정 중 본문: 실제 산출물의 `textRevision`을 표시해 새 회차 작업과 이전 본문을 구분한다. 현재 표시 중인 이전 본문과 겹치는 이력 항목은 제외한다.
