# FLOW-001 · 필수 단계·현재 회차 검증

- 순서: 진단→주제→독자→가치→근거→구성→초고→검토 순으로 진행한다. 새 글에서 단계를 줄이거나 중복하거나 거꾸로 세운 실행 계획은 거부한다.
- 완료: 각 단계의 구조와 필수 내용, 현재 회차의 선행 산출물을 검증한 뒤 다음 단계로 넘어간다. 누락되거나 조작된 상태로는 AI 요청과 TXT 인계를 할 수 없다.
- 수정: 현재 초안 이력을 보존하고 회차를 높인 뒤 수정할 위치를 판정한다. 검증된 선행 결과만 원래 회차 추적 정보와 함께 새 회차로 이어받고, 복귀 단계부터 그 뒤 단계를 다시 생성한다.
- 기존 부분 초안: 조회, 원고, 다운로드, 이력을 보존하며 AI에 자동으로 다시 요청하지 않는다. 사용자가 `complete_requirements` 동작으로 기존 작업의 중단을 확인한 뒤 새 회차의 전체 단계를 실행한다.
- 보완 실패: 중단이 불명확하면 pending 상태와 원고를 보존하고, 새 AI 생성과 중복 실행을 막는다. 같은 operation ID를 재사용하고 오래된 version을 거부하는 규칙은 유지한다.
- 화면: 전체 8단계의 대기, 진행, 완료, 중단, 실패 상태와 실제 시각, 단계별 결과를 표시하며, 이전 산출물과 현재 회차를 구분한다.
- 예산: 최초 실행은 최대 8회, 수정과 명시적 재개는 최대 9회로 제한한다. 요청 기한을 적용하고 전체 실행은 1,800초로 제한하며, 단순 재연결로 예산을 초기화하지 않는다.
- 사용자 판단: 준비, 초안 확정, 선택적 시각자료, 발행 준비 승인 단계로 진행하며, 모두 현재 회차의 사용자 입력만 허용한다. 수정하면 확정과 승인은 무효가 되며, 실제 발행은 별도로 처리한다.
- 검증: editorial-machine, service, prompts, paseo 단위 검증을 마친 뒤 격리 n8n과 HTTP fixture 검증을 거치고, PC·모바일 환경에서 전체 단계, 기존 초안 보완, 실패 복구를 검증한다.
