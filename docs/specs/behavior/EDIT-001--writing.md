# 글쓰기 작업 · `EDIT-001`

- 근거: 사용자가 작업을 재현할 때 JSON·서버·파일 경로 지식을 알아야 하는 문제를 해소하고, 한 화면에서 입력·검토·수정·복구를 요청할 수 있게 한다.
- 사용자: 대상 사용자는 로컬 블로그 소유자이며, 결과물은 직접 읽고 수정하거나 내려받을 수 있는 초안이다.
- 진입: `mise run editorial`을 실행하면 글쓰기 화면의 주소를 출력한다. 모델 기본값은 Hydrogen 4 Medium이다(2026-11-14 Flash 3.8 대체, Hydrogen low·medium·high 비교 근거).
- 경계: 서비스가 편집 규칙, 상태, 호출 한도, 중복 방지를 관리하고, n8n은 요청 전달과 대기를 맡으며, Paseo는 AI 실행을 맡는다.
- 저장: `.local/ai-runtime/editorial.sqlite`에 원문·초안·수정 이력을 저장하며, 외부 발행은 하지 않는다.
- 백업: 서비스 종료 후 `.local/ai-runtime/`의 비공개 사본을 만들어 SQLite, AI 작업 파일, 자격증명을 함께 보존한다.

## 선택

| 대안                  | 장점                                         | 제약·선택                                      |
| --------------------- | -------------------------------------------- | ---------------------------------------------- |
| 노드 코드 편집        | 기존 구성을 활용한다.                        | 사용자 운영 지식을 요구하므로 제외한다.        |
| n8n 기본 폼           | 입력 접수가 간단하다.                        | 진행·중단·복귀 화면을 추가해야 하므로 단독 사용에서 제외한다. |
| 기존 편집 서비스 화면 | 진행·결과·수정·복구를 한 화면에서 처리하며 새 서버가 필요 없다. | 로컬 전용으로 사용한다(선택).                  |
| CMS 통합              | 기존 글 관리와 연결된다.                     | CMS 변경 범위가 커지므로 독립 사용을 검증한 뒤 검토한다. |

## 행동·복구 계약

| 상태           | 표시·행동                                  | 보존·완료 근거                                  |
| -------------- | ------------------------------------------ | ----------------------------------------------- |
| 입력           | 글감은 필수이고 원문·출처는 선택이며, '초안 만들기'로 요청한다. | 입력을 임시 보존하며, 중복 제출은 같은 작업으로 처리한다. |
| 진행           | 실제 단계와 중단 동작을 표시하고, 완료된 본문이 있으면 함께 보여 준다. | 서버 상태를 보존하며, 새로고침 후에도 같은 작업을 조회한다. |
| 결과           | 본문, AI 검토 의견, 다운로드, 수정 요청을 제공한다. | 현재 회차의 다운로드 바이트와 본문이 일치한다. |
| 수정           | 요청 내용을 입력하여 수정을 시작한다.      | 이전 초안을 보존하며, 현재 버전과 충돌하면 최신본을 조회한다. |
| 중단           | 중단 확인 결과와 이어가기 동작을 제공한다. | 확인되지 않은 취소는 중단 성공으로 표시하지 않는다. |
| 실패·연결 끊김 | 보존된 결과, 멈춘 단계, 실패 종류, 이어가기 동작을 표시한다. | 같은 작업에 재연결하며, 확인하기 전에는 새 AI 작업을 생성하지 않는다. |
| 삭제           | 목록에서 삭제할 때는 확인 후 목록에서 숨긴다. | 진행 중이면 거부하고, 삭제 뒤에도 원고·이력 보존과 링크 조회는 유지한다. |

- 초기 흐름: 필수 8단계로 구성하며 최대 8회까지 호출한다. 사용자 수정이나 명시적 재개 요청당 최대 9회까지 허용하고, 다른 모델로 자동 대체하지 않는다(FLOW-001).
- AI 검토는 정확성 보증, 사용자 만족, 발행 승인과 별개이다. 원문과 출처는 사용자가 제공한 자료를 사용하며, 별도로 웹을 조사하지 않는다.
- 좁은 폭·확대: 한 열로 재배치하고 본문 줄바꿈과 키보드 기반 제출·복구를 지원한다. 상태가 바뀌어도 입력 포커스와 스크롤 위치는 옮기지 않는다.
- 개인정보: 데이터는 로컬에 저장하며, AI를 실행할 때는 제공자에 필요한 내용만 전달한다. 원문과 비밀값은 로그에서 제외한다.
- 검증: 전용 n8n, 임시 SQLite, fixture AI 환경에서 입력→본문→다운로드→수정→중단→복구 흐름을 확인하고, PC와 모바일 화면을 직접 눈으로 확인한다.
- 명령: 검증 명령은 `mise run test:editorial`, `mise run test:paseo`, `mise run test:e2e`(TEST-RUN)이며, 브라우저 설정은 `playwright.ai-writing.config.ts`를 사용한다.
- 시작 준비: 기존 로컬 n8n 개발 계정과 브리지 자격증명을 사용하고 이미 실행 중인 서버를 재사용한다. 생성·관리 중인 워크플로는 바꾸기 전에 비공개 백업을 만든다.
- 실제 AI 호출과 fixture 검증을 구분한다. 사람 대상 사용성 연구와 접근성 인증은 제외한다.
- 부분 초안: 보존된 원고·이력과 보완이 필요한 이유를 표시한다. 사용자가 필수 단계 보완을 요청하기 전에는 새 AI 실행을 시작하지 않는다.
- 결과 확인: 단계별 산출물, 초안 확정, 선택적 시각자료, 발행 준비 승인을 제공한다. 실제 발행은 별도이며, 글을 수정하면 확정·시각자료·승인은 무효화한다.
