# 사용자 입력 도크 · `DOCK-001`

- 근거: 본문을 읽다가 아래로 다시 스크롤해야 수정 요청과 수정 해석 확인을 할 수 있다는 사용자 지적을 반영한다.
- 계약: 작업 화면에서 받는 사용자 입력과 결정, 실시간 미리보기는 화면에 떠 있는 작업 도크 한 곳에서만 처리하고, 본문 흐름에는 결과와 기록만 둔다. 도크가 받는 입력과 결정은 다음과 같다.
  - 수정 요청, 수정 해석 확인, 필수 단계 보완
  - 초안 확정, 시각자료 위치 선택, 시각자료 확인, 발행 준비 승인
- 탭: 확인, 실시간, 수정 요청 순으로 배치하며 해당 상태일 때만 표시한다. 표시할 탭이 하나뿐이면 탭 줄을 생략한다.
- 열림: 평소에는 접힌 표시줄로 유지하여 본문 레이아웃이 움직이지 않게 한다.
  - 작업을 멈추는 결정(수정 해석 확인, 보완, 시각자료 위치 선택, 시각자료 확인)이 도착하면 확인 탭으로 펼친다.
  - 진행 상황과 초안 확정은 표시줄 문구와 점으로만 알린다.
  - 닫을 때는 Esc 키를 누르거나 접기 동작을 쓴다.
- 폭·스크롤: PC에서는 오른쪽 아래에 두고, 좁은 폭에서는 아래쪽 전체 폭 시트로 띄운다. 긴 양식은 도크 안에서만 스크롤한다.
- 검증: PC와 모바일 E2E 테스트가 도크에서만 입력이 이루어지는지 검증하며, 접힌 상태의 입력 요소는 `inert`로 처리한다.
