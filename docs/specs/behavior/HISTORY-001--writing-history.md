# 작성·수정 과정 · `HISTORY-001`

- 근거: 실행 로그보다 ‘요청을 어떻게 해석했는가·무엇을 바꿨는가·무엇을 확인해야 하는가’를 알고 싶다는 사용자 의견을 반영한다.
- 진입: 본문 앞의 ‘글이 만들어진 과정’에서 연다. 현재 초안은 먼저 펼치고 이전 초안은 접어 두며, 상세 작성 자료, 원문 입력, 기술 기록은 별도로 접어 둔다.
- 기본 표시: 요청한 수정, 저장된 작성·수정 요약, 독자·핵심·구성에 관한 선택과 이유, 읽으며 확인할 점을 표시한다.
- 반복 제거: 수정한 뒤 바뀐 작성 방향만 보여 주고, 확인할 점은 중복을 빼고 기본 2개를 먼저 보인 뒤 나머지는 펼쳐 보게 한다. 모델, 호출 수, 전달 경로, 요청·완료 사건은 기본 화면에서 제외한다.
- 근거 경계: 실제 저장된 산출물과 사용자 수정 요청만 조합한다. 내부 사고 과정이나 의도, 실제 반영 여부를 새로 추정하거나 AI에 요약을 따로 요청하지 않으며, 작성 요약은 저장된 AI 산출물을 사용한다.
- 과거 보존: 편집 DB에 회차별 산출물과 사건을 보존한다. 다시 열기, 새로고침, 후속 수정 후에도 같은 과정을 조회할 수 있으며, 원고는 기존 다운로드 계약을 사용한다.
- 문제 진단: 접힌 실행 기록에서 시각, 당시 자료 종류, 모델, 해당 n8n 실행, 확인된 실패 원인, 수정 경로, 단계 산출물을 제공한다.
- 자료 선택: `promptContext`를 정본으로 삼는다. 새 실행에서는 입력 종류 스냅샷을 보존하고, 과거 실행에서 자료 선택을 재구성한 경우에는 그 사실을 밝힌다. 작업 파일이 빠져 보존 산출물로 대체한 경우에는 당시 결과와 구분해 표시한다.
- 미기록 과거: 사건, 시각, 판단을 소급 생성하지 않는다. 조회 동작은 AI 실행이나 편집 상태 변경을 일으키지 않으며, 원시 프롬프트, 추론, 명령 인자, 진단 원문은 제외한다.
- 연결 실패: 조회한 과정을 유지하고 다시 불러오기 동작을 제공한다. 명시적으로 열 때만 조회하며, 읽던 위치를 유지하고 좁은 폭에서는 줄을 바꾼다.
- 검증: 작성 방향 변경과 유지, 실제 수정 요청, 중복 확인 사항, 빠진 근거, 과거 회차, 조회 멱등성, 인증을 검증하며, PC와 모바일에서 호출 수와 편집 버전이 바뀌지 않는지 확인한다.
