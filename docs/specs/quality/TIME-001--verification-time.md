# TIME-001 · 검증 시간 예산: 전체 검증은 5분 안, 실제 모델 실행은 검증에 묶지 않음

- 범위: `mise run verify`(정적·단위·격리 n8n·fixture 흐름·PC·모바일 브라우저)와 그 구성 작업 · 실제 모델 실행(`ai:pilot`·`ai:test:contract`·`ai:e2e:article`·`ai:eval`)의 실행 조건
- 기준: 캐시 없이 전체 300초 이내 · 작업별 예산과 단계 구성의 원본은 `tests/time-budget.mjs` · 환경: 개발 PC 1대(18코어), 다른 무거운 작업과 함께 돌 수 있음
- 측정 방법: `mise run verify`가 작업마다 걸린 시간을 재서 예산과 대조 · 실패 작업 또는 예산 초과가 있으면 0이 아닌 코드로 종료 · 캐시를 무시한 실측은 `mise run verify -- --force`
- 실측(2026-11-15): 정적·단위 8초 · 격리 n8n 34초 · fixture 흐름 34초 · 브라우저 106~173초 · 전체 212~249초
- 예산을 지키는 규칙
  - 실제 대기 금지: 운영 대기 간격(n8n 2초)을 실제로 기다리는 검증은 한 곳(`test:n8n:runtime`)뿐 · 여러 번 호출하는 흐름 검증은 간격을 줄여 쓴다(흐름 테스트 99 → 34초)
  - 벽시계 경주 금지: "N초 안에 끝나기 전에 누른다" 식으로 통과가 실행 속도에 달린 테스트를 두지 않는다 · 진행 중 상태가 필요하면 fixture가 테스트가 끝낼 때까지 그 상태를 유지한다(LIVE-001이 부하 시 실패하던 원인)
  - 같은 것을 두 번 검증하지 않음: 규칙은 단위에서, 연결은 통합에서 한 번 · 통합 테스트에 단위 사례를 되풀이하지 않는다
  - 브라우저 병렬 4: 8로 올리면 빨라지지 않고 타이밍 실패가 생김(실측)
- 예산 초과 시: 예산을 올리기 전에 느려진 원인을 찾아 걷어낸다 · 올릴 때는 실측과 이유를 `time-budget.mjs`에 적는다
- 실제 모델 실행
  - 검증(`verify`)과 다른 작업의 의존에 묶지 않는다 · 호출마다 비용이 들고 글 1편이 모델 응답 시간만으로 5~8분(호출 9~11회)이라 시간 예산 밖
  - 사람이 터미널에서 직접 실행한다 · 터미널이 아닌 실행(에이전트·CI·다른 작업에 묶인 실행)은 `AIN_LIVE=1` 없이는 시작 전에 거부(`paseo/live/consent`)
  - 에이전트는 사용자가 그 실행을 명시적으로 요청했을 때만 `AIN_LIVE=1`을 쓴다
  - `ai:eval` 기본은 글감 4종 × 1회 · 멱등성(반복 통과율)은 `--trials`로 명시
- 완료 기준: `mise run verify -- --force`가 예산 안에서 통과 · `tests/time-001.test.mjs`(예산 합이 상한 이내, 실제 모델 작업이 검증에 묶이지 않음, 터미널이 아닌 실행 거부)
- 한계: 브라우저 시간은 PC 부하에 따라 106~173초로 흔들림 · 모바일 프로젝트가 같은 14건을 한 번 더 돌림(PC·모바일 E2E는 프로젝트 기준이라 유지, 화면 크기와 무관한 사례를 PC 전용으로 옮기면 약 1분 절감 가능)
- 관련: OPS-003 · TOOL-001 · JUDGE-001
