# TIME-001 · 검증 시간 예산: 전체 검증은 5분 이내, 실제 모델 실행은 검증에 포함하지 않음

- 범위: `mise run verify`(정적, 단위, Go 합성 흐름, PC·모바일 브라우저 경로)와 그 구성 작업 및 실제 모델 실행(`ai:pilot`, `ai:test:contract`, `ai:e2e:article`, `ai:eval`)의 실행 조건을 다룬다.
- 기준: 캐시 없이 전체 300초 이내로 완료해야 한다. 작업별 예산과 단계 구성의 원본은 `tests/time-budget.mjs`이며, 기준 환경은 다른 무거운 작업과 함께 실행될 수 있는 개발 PC 1대(18코어)이다.
- 측정 방법: `mise run verify`가 작업마다 소요 시간을 측정해 예산과 대조하며, 실패한 작업이나 예산 초과가 있으면 0이 아닌 코드로 종료한다. 캐시를 무시하고 실측하려면 `mise run verify -- --force`를 실행한다.
- 레거시 기준 실측(2026-11-15): 정적·단위 8초, 격리 n8n 34초, fixture 흐름 34초, 브라우저 106~173초로 전체 소요 시간은 212~249초이다.
- 예산을 지키는 규칙
  - 실제 대기 금지: Go 흐름 검사에는 합성 제공자를 사용하고 운영 환경의 재조회 간격을 기다리지 않는다. n8n 실프로세스 검증은 레거시 재현 작업으로 개별 실행한다.
  - 시간 경합 금지: "N초 안에 끝나기 전에 누른다"와 같이 통과 여부가 실행 속도에 달린 테스트는 두지 않는다. 진행 중 상태가 필요하면 fixture가 테스트 종료 시점까지 그 상태를 유지한다(LIVE-001이 부하 시 실패하던 원인).
  - 같은 것을 두 번 검증하지 않음: 규칙은 단위 테스트에서, 연결은 통합 테스트에서 한 번씩만 검증하며, 통합 테스트에 단위 사례를 되풀이하지 않는다.
  - 브라우저 병렬 4: 병렬 수를 8로 올리면 빨라지지 않고 타이밍 실패가 발생한다(실측).
- 예산 초과 시: 예산을 올리기 전에 느려진 원인을 찾아 제거한다. 예산을 올릴 때는 실측치와 이유를 `time-budget.mjs`에 기록한다.
- 실제 모델 실행
  - 검증(`verify`)과 다른 작업의 의존에 포함하지 않는다. 호출마다 비용이 발생하고 글 1편이 모델 응답 시간만으로 5~8분(호출 9~11회)이 걸려 시간 예산을 초과하기 때문이다.
  - 사람이 터미널에서 직접 실행한다. 터미널이 아닌 실행(에이전트, CI, 다른 작업에 연동된 실행)은 `AIN_LIVE=1`이 없으면 시작 전에 거부한다(`paseo/live/consent`).
  - 에이전트는 사용자가 해당 실행을 명시적으로 요청했을 때만 `AIN_LIVE=1`을 사용한다.
  - `ai:eval`의 기본값은 글감 4종 × 1회이며, 멱등성(반복 통과율)을 검증할 때는 `--trials`를 명시한다.
- 완료 기준: `mise run verify -- --force`가 예산 안에서 통과해야 한다. 또한 `tests/time-001.test.mjs`에서 예산 합, Go 경로 포함 여부, 실제 모델 작업 제외와 비대화형 호출 거부를 확인한다.
- 한계: 브라우저 시간은 PC 부하에 따라 106~173초 사이에서 달라진다. 모바일 프로젝트가 같은 14건을 한 번 더 실행한다(PC·모바일 E2E는 프로젝트 기준이므로 유지하되, 화면 크기와 무관한 사례를 PC 전용으로 옮기면 약 1분을 절감할 수 있다).
- 관련: OPS-003, TOOL-001, JUDGE-001이다.
