# JUDGE-001 · 글 품질 판정 경계: 코드는 세고 대조하고 뜻은 검토(LLM)가 판정한다

- 범위: 산출물(구성·초고)의 품질 판정과 그 근거 자료, 검토 입력 지표(`paseo/metrics`), 코드 검증(`editorial/domain`의 sections·requirements), 반복 평가 채점(`paseo/live/grade`)을 다룬다.
- 코드가 판정하는 것(판정 근거 basis)
  - count: 글자·문장·문단·구간의 수와 길이, 문법 기호(소제목·굵게·물음표)의 개수를 센다.
  - exact: 계약에 적힌 문자열·구조와 글자 그대로 일치하는지 대조한다(구성의 제목·소제목·카드 항목이 초고에 실렸는지, 항목이 채워졌는지).
  - process: 실행 기록(회차·호출 수·완료 여부)과 출력 형식(schema)을 확인한다.
- 검토(LLM)가 판정하는 것: 뜻을 읽어야 하는 모든 기준이 여기에 속한다. 말투·시점의 일관성, 과장, 도입부 역할, 용어 풀이, 사례가 원칙을 보여 주는지 여부, 사실 근거를 점검표 `seasoning.CHECKS`의 예·아니오 응답과 근거 표현 인용으로 판정하며, 코드는 그 결과(review)를 집계만 한다.
- 금지: 낱말·어미 목록이나 정규식으로 글의 뜻·어조·질을 판정하거나, 그런 값을 판정 근거 지표로 삼아 검토에 넘기지 않는다.
- 금지 이유(실측 2026-11-15): 되묻는 문장 "누구나 …할 수 있을까?"가 과장어로 집계되었고, 호칭 낱말 비율 0을 근거로 검토가 '독자에게 말하지 않음'으로 판정하였으며, 본문에서 풀이된 용어가 미풀이 후보로 넘어가 미통과 처리되었다. 낱말은 문맥을 모르고, 검토는 넘겨받은 수치를 근거로 삼기 때문이다.
- 금지 아님: 형식 토큰화(문장 경계·마크다운 문법), 사용자 입력의 수량 표현 읽기(분량 `parseLength`, 구조화 입력 우선), 프롬프트에 싣는 예시 낱말(작성 안내이며 판정이 아님)은 금지에 해당하지 않는다.
- 확장 절차
  - 새 코드 지표: `METRIC_BASIS`에 count 또는 exact로 등록한다. 둘 중 어느 것도 아니면 코드 지표가 아니다.
  - 새 채점 기준: `GRADERS`에 basis와 함께 추가한다. 뜻 판정이 필요하면 basis는 review만 사용한다.
  - 새 의미 기준: `seasoning.CHECKS`에 예·아니오 질문으로 추가한다. 근거로 인용할 코드 측정값은 등록된 지표만 사용한다.
- 실패 복구: 검토 판정이 일관되지 않으면 질문을 더 좁은 예·아니오 질문으로 나누거나 근거 인용을 요구하며, 코드 기반 단순 추정 방식으로 되돌리지 않는다. 판정의 일관성은 `ai:eval`의 점검표 항목별 미통과 횟수로 판단한다.
- 완료 기준: `draftMetrics` 출력 키가 `METRIC_BASIS`와 일치하고 근거가 count·exact뿐이며, `GRADERS` 근거가 count·exact·process·review뿐인지 확인한다. 또한 판정 코드에 한글 낱말을 담은 정규식이 허용 목록(문장 경계) 밖에 없음을 `tests/judge-001.test.mjs`로 검증한다.
- 한계: 자동 검사는 정규식 리터럴과 등록부를 확인한다. 문자열 낱말 목록을 `includes`로 대조하는 방식의 우회는 탐지하지 못하므로 코드 리뷰에서 이 기준에 따라 점검해 걸러낸다.
- 관련: ADR-0013, ADR-0007, RES-007이다.
