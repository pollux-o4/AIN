# LAB-001 · 시각자료 연구소

- 목적: 같은 사례를 현재 방식과 변형(A·B…)으로 돌린 결과를 한 형식으로 남겨 나란히 비교하고, 실험을 다른 에이전트·세션에 인계한다.
- 대상: 위치 제안(plan)과 그림 생성(figure) 단계이다. 글 품질 실험은 `ai:eval`이 맡는다.

## 구성

| 요소 | 위치 | 역할 |
| --- | --- | --- |
| 기록 계약 | `automation/contracts/lab.mjs` | 기록 형식과 사례 × 변형 비교표(`labMatrix`)의 단일 정의 |
| 변형 목록 | `automation/paseo/lab/variants.mjs` | 비교할 조건과 가설. 기준 변형 `baseline`은 항상 첫 열이다. |
| 저장소 | `.local/figure-lab/<사례>/<변형>/<단계>-<회차>/` | `record.json`과 결과 파일. 원문이 섞일 수 있어 커밋하지 않는다. |
| 비교판 | Storybook `연구소/실험 기록` | 색인 `lab.json`과 결과 파일만 읽는다. 화면 점검은 `연구소/예시`로 한다. |

## 실험 절차

1. 가설을 변형 목록에 항목 하나로 더한다. 바꾼 것(`changes`)과 기대 결과(`hypothesis`)를 적는다.
2. 기준 변형과 같은 사례·같은 입력으로 실행한다. 멱등성을 볼 때는 회차를 늘린다.
3. 결과를 기록으로 남긴다. 앱 실행 기록은 `mise run lab:import -- <글 id 앞부분> <사례> <변형> [회차]`로 가져오고, 별도 진입점은 `writeLabRecord`로 쓴다.
4. 그림 에이전트의 도구 기록이 있으면 시각 확인 집계(렌더·열람·열람 뒤 수정 횟수)를 `visual`에 적는다. 없으면 비워 둔다.
5. 판정은 비교판에서 그림을 본 사람이나 검토가 내리고 `mise run lab -- judge …`로 기록한다. 코드는 시간·토큰·횟수만 집계한다(JUDGE-001).
6. 채택한 변형은 ADR로 결정하고, 기준 변형의 설명을 갱신한다.

## 인계 기준

- 인계받는 쪽은 비교판과 변형 목록만 보고 실험 상태를 알 수 있어야 한다. 별도 메모가 필요하면 기록의 `note`에 적는다.
- 실제 모델 실행은 사용자의 요청이 있을 때만 한다(TIME-001).
- 변형은 현재 실행 당시의 코드 기준(`ref`)으로만 구분한다. 같은 코드에서 변형을 동시에 돌리는 기능은 아직 없다.
