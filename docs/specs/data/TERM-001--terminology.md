# 용어 · `TERM-001`

- 범위: 문서, AI 지시문, 화면 문구, 코드 주석에서 같은 개념을 같은 이름으로 부른다. 코드 식별자는 바꾸지 않고 아래 표로 대응시킨다.
- 기준: 처음 읽는 사람이 설명 없이 뜻을 짐작할 수 있는 일반 낱말을 쓴다. 비유로 만든 내부 별칭은 쓰지 않는다(ADR-0019).
- 변경: 용어를 바꿀 때는 이 표를 먼저 고치고, 같은 변경 단위에서 문서·지시문·화면·주석을 함께 바꾼다. 옛 이름은 검색용으로 '이전 이름' 열에만 남긴다.

## 글 구조

| 정식 용어 | 뜻 | 코드 식별자 | 이전 이름 |
| --- | --- | --- | --- |
| 도입부 | 글 제목 줄부터 첫 소제목 앞까지. 독자의 상황을 짚고 얻을 것을 밝힌다(ADR-0021) | `lead`, `LEAD_UNIT` | 글머리 |
| 구간 | `##` 소제목 하나가 여는 본문 단위 | `section`, `sections` | |
| 하위 항목 | 구간 안의 `###` 이하 단위 | `subsections` | 마디 |
| 끝 정리 | 글 끝 `## 한눈에 정리` 목록 | `summaryHeading` | |

## 구간 카드 (구성 단계가 구간마다 채우는 설계)

| 정식 용어 | 뜻 | 코드 식별자 | 이전 이름 |
| --- | --- | --- | --- |
| 구간 카드 | 구성 단계가 구간마다 채우는 항목 묶음. 초고는 이를 문장으로 옮긴다 | `sectionCard` | 이야기 카드, 구성 카드 |
| 항목 | 구간 카드나 산출물에서 값을 채우는 자리 하나 | `slot` | 칸 |
| 여는 질문 | 구간의 첫 문장이 될 질문이나 통념을 뒤집는 주장 | `hook` | |
| 사례 | 원칙을 장면으로 보여 주는 이야기 | `cases` | |
| 강조 문장 | 구간의 핵심을 기억하기 쉽게 쓴 굵은 글씨 1문장 | `underline` | 밑줄, 밑줄 문장, 핵심 문장 |
| 마무리 문장 | 구간 끝에서 독자가 가져갈 판단이나 행동 1문장. 끝 정리에 모인다 | `principleLine` | 닫는 줄, 한 줄 원칙 |
| 핵심 원칙 | 구간이 전달할 원칙 1문장 | `keyPoint` | |
| 약속 문장 | 이 글을 읽고 나면 할 수 있는 일 1문장 | `promise` | |
