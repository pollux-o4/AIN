# ADR-0007 · 상태 머신 가드로 코드 판정 요구사항을 강제한다

- 맥락: 분량 요구(4,500자)가 글감 문장에만 적혀 있고 전이 조건은 아니어서, review 결과와 상관없이 `awaiting_user`로 넘어가고 수정을 2회 한 뒤에도 8,363자에 머물렀다.
- 대안: 검토 AI의 지적에 기대는 방식, 편집장(ADR-0006)이 매번 되돌리는 방식, 상태 머신 가드 방식을 검토하였다.
- 선택:
  - review가 끝나면 `requirements.mjs`로 검사하고, 충족하지 못하면 새 회차를 열어 검사가 지정한 단계부터 다시 작성한다.
  - 분량이 어긋나면 1차는 outline에서 예산을 다시 배정하고, 그다음부터는 구간별 실제 글자 수와 삭감량을 함께 주어 draft를 줄여 맞춘다(모델이 예산을 60% 넘게 넘긴 실측에 따른 것이다).
  - 상한은 `AUTO_CORRECTION_LIMIT`(2)회로 정하고, 이를 다 쓰면 `awaiting_user` 상태로 바꾸고 `unmet`를 기록한다.
  - 분량 등 코드 판정 미충족이 남아 있으면 `satisfy`를 거부한다(`blockingUnmet`). 다만 검토 판정(`kind: review`)은 주관적 판정이므로 사람 판단으로 승인할 수 있다.
- 이유:
  - 결정적으로 판정하고 테스트로 동작을 고정할 수 있다.
  - AI가 피드백을 만드는 것이 아니라 코드 규칙으로 거르는 것이므로 FLOW-002의 "AI 자체 피드백 금지" 원칙과 어긋나지 않는다.
  - 상한과 회차 예산으로 무한 반복을 차단한다.
- 요구 원천: 요구사항 목록(ADR-0016)으로 대체한다. 자동 보정 지시문은 요구사항 목록에 적지 않는다.
- 결과:
  - 자동 회차마다 새 실행 예산을 부여하고 이벤트 `auto_correction`을 기록한다.
  - 사람이나 편집장의 피드백이 들어오면 보정 횟수를 초기화한다.
  - 프롬프트에는 `requirements`를 전달하며, 구성 단계에서는 글자 예산을 배정한다.
- 확장: `CHECKS`에 종류별 검사기(target, evaluate)를 추가하고, 값은 요구사항 목록에서 가져온다. 여러 항목을 충족하지 못하면 가장 앞 단계로 되돌린다.
- 갱신(2026-11-11): 상한을 다 쓴 뒤에도 7,460자 원고가 만족 승인이 가능한 상태로 넘어간 실측이 나와 승인 차단을 추가하였다. 이 상태는 사람 피드백(새 요구 또는 새 회차)으로 푼다.
- 관련: FLOW-002, ADR-0006, RES-005
