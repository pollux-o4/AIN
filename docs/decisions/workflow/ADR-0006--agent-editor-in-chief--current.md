# ADR-0006 · 위임받은 에이전트의 편집장 역할과 사람의 최종 검수

- 맥락:
  - 기획·조사·작성·검토 담당은 분리되어 있으나, 검토 결과를 보고 되돌릴지 넘길지 판정하는 역할이 없다.
  - 그래서 분량이 3배나 되는 초안도 "초안 준비됨" 상태로 사람에게 넘어간다.
  - FLOW-002에는 AI 내부 자동 피드백 금지 원칙이 있다.
- 대안: AIN 내부 편집장 AI가 자동으로 되돌리는 방식, 담당 간 자유 대화(다중 에이전트), 위임받은 외부 에이전트가 CLI로 판정하는 방식을 검토하였다.
- 선택: 위임받은 에이전트가 편집장 역할을 맡는다. 다만 에이전트에게는 `feedback`만 허용하고, `satisfy`와 `authorize_publication`은 사람만 할 수 있다.
- 이유:
  - 상태 머신을 결정적으로 유지할 수 있다.
  - 판정 근거가 대화에 남아 사람이 즉시 교정할 수 있다.
  - 내부 자동 피드백 금지 원칙과 어긋나지 않는다.
  - 자유 대화 방식은 비용과 재현성을 통제할 수 없다.
- 강제(서버):
  - 에이전트 토큰 요청의 actor는 `agent`로 처리하며, 최종 검수를 요청하면 403을 반환한다.
  - 사람 행동 없이 에이전트가 연속으로 `EDITORIAL_LIMITS.agentFeedbackRounds`(2)회를 넘겨 수정하면 409를 반환한다.
  - 이벤트는 `by`와 라벨 "편집장 수정 요청"으로 기록한다.
- 판정 근거: 리뷰 findings, 코드 지표 `draftMetrics`, 사용자 요구(idea)를 토대로 삼고, 판정 기준은 스킬 `ain-write`를 따른다.
- 결과: 위임 범위 안의 수정은 매번 비용 승인을 받지 않아도 된다. 다만 상한에 이르거나 같은 지적이 반복되면 사람에게 보고한다.
- 변경: 수정 해석과 합격 판정은 AIN 내부로 옮겼다(ADR-0008). 이 문서에서는 외부 에이전트의 권한(수정 지시 상한과 최종 검수 금지)에 관한 내용만 유효하다.
- 관련: ADR-0005, AGENT-001, RES-005
