# ADR-0018 · 문장 편집과 교열 수정은 변경 표시로 낸다

- 맥락: 수정 해석은 수정 수준(developmental·line·copy, RES-006)을 정하지만, 결과물은 모든 수준에서 "원고 통째로 다시 쓰기" 하나뿐이었다. 그래서 부분 수정이 요청한 곳에만 머무는지를 작성 AI가 "지적받지 않은 부분은 그대로 둔다"는 지시를 따르는지에 기댔고, 수정을 요청하지 않은 문장이 임의로 바뀌어도 알 수 없었다(2026-11-17 사용자 지적).
- 원칙: 편집 수준이 결과물의 형식을 정한다. 구조 편집의 결과물은 새 원고이고, 문장 편집과 교열의 결과물은 원고 위의 변경 표시(tracked changes)이다.
- 선택:
  - 적용 조건: 수준이 line·copy이고 초고부터 다시 작성하는 회차이며 직전 원고가 있으면, 초고 작업은 `mode: "edit"`가 된다(`marksChanges`). 그 밖의 경우에는 기존대로 구간별 또는 한 번에 작성한다.
  - 결과 계약 `draftEditSchema`: `edits[{find, replace}]`와 `changeSummary`로 구성한다.
  - 적용: 코드가 각 find를 직전 원고(baseline)와 글자 그대로 대조한다. find가 한 번만 나오고 서로 겹치지 않을 때만 적용하므로, 표시하지 않은 글자는 구조상 바뀌지 않는다.
    - 어긋난 표시는 사유와 함께 반려하고 다시 요청한다. 다시 쓰기 상한을 넘기면 실패로 멈추며 원고는 바뀌지 않는다.
    - 대조는 일치 여부 확인만 하고 뜻은 판정하지 않는다(JUDGE-001).
  - 기록·표시: 적용한 표시는 초고 산출물의 `edits`로 보존한다. 화면과 CLI는 이번 회차 변경 표시(삭제한 글 → 추가한 글)를 보여 준다. 사람은 원고 전체를 다시 읽지 않고 바뀐 곳만 확인한다.
  - 계획 동기화: 변경 표시가 구간 카드와 약속 문장(`outline`·`value`)에서 온 문장을 수정하면 구간 카드도 같은 값으로 바꾼다. 변경 표시의 범위가 구간 카드 문장보다 넓으면 바뀐 부분만 글자 대조로 옮긴다. 그렇지 않으면 구간 카드 대조 검사가 사람이 승인한 수정을 누락으로 오판하여 구성부터 다시 작성한다(2026-11-17 실측: 강조 문장 수정 뒤 구성 재작성으로 제목과 도입부가 유실됨).
  - 제외 사항: 변경량 상한과 경고, "같은 지적 반복" 자동 판정은 두지 않는다. 둘 다 특정 사례에 맞춘 임계값이거나 뜻 판정이기 때문이다.
- 결과: 국소 수정의 범위를 코드가 보장한다. 구조 편집은 바뀌지 않는다.
- 관련: ADR-0008, ADR-0009, ADR-0010, RES-006, JUDGE-001
