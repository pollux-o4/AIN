# ADR-0003 · 필수 단계와 명시적 보완

- 맥락: FLOW-001이 정한 필수 8단계와 기존 축약 실행·회차 승계 방식이 서로 맞지 않는다.
- 선택: 순수 상태 머신이 전체 plan의 정확성과 현재 회차 선행 결과를 검증해 강제한다. 서비스, 원시 n8n, TXT 인계가 모두 같은 검사를 쓴다.
- 기존 데이터:
  - 조회만 할 때는 상태를 바꾸거나 자동으로 다시 실행하지 않는다.
  - 사용자가 보완을 요청하면 이전 원고를 이력에 남기고 새 회차를 시작한다.
  - 중단을 확인하기 전에는 pending을 바꾸지 않는다.
- 수정: 다시 검증한 선행 산출물만 원래 회차 추적 정보와 함께 승계한다. 수정 위치 이후의 결과, 만족, 승인은 모두 무효로 돌린다.
- 대안: 축약 실행 허용, 기존 상태 자동 덮어쓰기, 명시적 보완 세 가지를 검토하였다. 마지막 방안을 택해 기존 작업, 비용, 원문을 보존한다.
- 실행 한도: 8단계와 라우팅 1회를 허용한다. 다시 연결해도 예산을 초기화하지 않으며, 기한과 중단 확인을 그대로 둔다.
- 경계: 글 준비, 사용자 만족, 발행 준비 승인은 연결하되, 실제 발행은 별도로 둔다.
