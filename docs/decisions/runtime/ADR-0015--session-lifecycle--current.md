# ADR-0015 · Paseo 세션 수명은 소유 표시와 주기 정리로 관리한다

- 맥락: 담당 재사용(대기 세션)과 검증 실행(`ai:test:contract`·`ai:eval`) 뒤에 종료되지 않은 세션이 남았다. 2026-11-17 실측에서 AIN 표시 세션 166개 중 158개가 이미 끝난 검증 실행의 대기 담당 세션이었고, 제공자 프로세스 130개가 약 8.1GiB를 차지하고 있었다.
- 원인: 대기 세션 해제가 "같은 글의 다음 단계가 가져감"에만 기대고 있었다. 사람 피드백을 기다리거나 실행 또는 런타임이 끝날 때 세션을 해제하는 경로가 없었고, 세션에 소유 런타임 표시도 없었다.
- 대안:
  - 작업이 끝날 때마다 모두 보관하는 방안은 세션 재사용의 이점을 잃는다.
  - 검증 실행에만 정리를 추가하면 서비스에서 세션이 계속 쌓이는 문제는 해결하지 못한다.
  - 소유 표시와 정책 기반 주기 정리를 함께 적용하기로 하였다.
- 선택: 소유 표시와 정책 기반 주기 정리를 적용하고, 정책 정의는 `paseo/lifecycle.mjs` 한 곳에 둔다.
  - 표시: 모든 세션에 `labels{source, owner(작업 저장소 절대 경로), job}`를 붙인다.
  - 정책 `SESSION_POLICY`: 대기 담당의 유휴 한도는 15분, 총량 상한은 6개(오래 대기한 세션부터 해제)로 정하며, 방금 끝난 세션은 결과 회수 전 2분간 유예한다.
  - 정리 대상: 진행 중인 작업이나 유지할 대기 담당에 속하지 않는 이 런타임의 세션, 소유 경로가 사라진 세션, 표시가 없고 이 런타임의 작업 폴더 밖에 있는 이전 세션을 정리한다.
  - 시점: 서비스 실행 중에는 60초마다 정리하고, 서비스나 검증 실행이 끝날 때는 대기 담당까지 전부(`all`) 정리한다. 수동 정리는 `mise run ai:prune`으로 실행한다.
- 결과: 세션 수가 진행 중인 작업 수와 대기 상한 안쪽으로 유지된다. 대기 세션이 해제된 뒤 다음 단계가 실행되면 새 세션을 열어 첫 턴 전체를 보낸다.
- 제약: 표시가 없는 이전 세션이 이 런타임의 작업 폴더 밖에 있으면 소유자가 없는 것으로 본다. 따라서 이 변경 전 코드로 동시에 돌고 있는 검증 작업이 있으면 그 대기 담당 세션도 함께 정리된다.
- 관련: ADR-0013(담당 재사용)
