# ADR-0026 · 위치 선정과 구성을 나누고, 구성은 고른 자리 전부를 한 번에 정한다

- 맥락: 위치 제안 한 번에 후보 16~18개의 자리·주장·장면·비유·대응표·일관성 계약을 모두 정하였다. RES-009에서 지시문 충돌을 고친 뒤에도 후보마다 장면 셋을 비교하라는 요구가 실행되지 않았다. 비용이 큰 생성 전에 사람이 "무엇을 그릴지"를 확인할 지점도 없었다.
- 선택: 그림 흐름을 다음 순서로 나눈다.
  1. 위치 선정(AI, `figure_plan`): 글 전체에서 자리(anchor)·보여 줄 관계(claim)·이유(reason)·없으면 놓치는 것(without)·유형(kind)만 정한다.
  2. 자리 검수(사람, `awaiting_figure_choice`): 자리를 고르고 방향(direction)·경로(route)를 덧붙인다.
  3. 구성(AI, `figure_compose`): 고른 자리 전부를 글 전체와 함께 한 번에 받는다. 장면 세계(world) 하나와 자리마다 analogy·scene·mapping을 정하고, 일관성 계약(style·motifs, ADR-0022)도 여기서 정한다. 자리마다 따로 구성하면 그림마다 다른 세계가 되므로 나누지 않는다.
  4. 구성 검수(사람, `awaiting_figure_design`): 승인하면 생성으로 넘어간다. 의견을 주면 구성을 다시 한다.
  5. 생성(AI, `figure`): 그림 한 장씩 그리기 한 층(`draw`)으로 만든다. 한 층 안에서 준비(키트 서명 목록) → 세부까지 한 번에 작성 → 글자 뺀 렌더링으로 자기 판정 → 마감·배치를 구간 편집으로 한 번에 차례로 밟는다. 원본 전체 재작성은 비유 대상·구도를 바꿀 때로 한정한다. 초안·시각 두 층은 같은 세션의 인계와 재확인만 늘려 합쳤다(RES-009). 고른 그림은 동시에 그린다. 확인 렌더링은 범용 배치 점검 도구(글자 겹침·잘림·글자를 지나는 선과 빈자리 후보, 글자 뺀 PNG, 내용에 맞춘 viewBox 후보)로 한다. 층과 수정 사이에는 SVG와 함께 그림을 만든 원본(`source`, 빌드 스크립트 등)을 넘긴다. 다음 층은 원본을 고쳐 다시 만들며, AIN은 원본 형식을 알지 못한 채 글자로만 보관한다.
  6. 피드백: 확인 단계에서 그림을 골라 되돌린다. 무엇을 그릴지의 문제면 구성(3)으로 보내 다시 구성한다. 어떻게 그렸는지의 문제면 직전 그림과 지적을 받아 지적한 부분만 고치는 수정 층(`fix`)을 한 번 돌린다. 처음부터 다시 그리지 않는다. 수정은 그림 한 장에 3회(`FIGURE_LIMITS.fixes`)까지이며, 넘으면 구성으로 보낸다. 다시 구성할 때 고르지 않은 자리의 구성과 world·계약은 유지한다.
- 결과:
  - 대상 정책(LAB-001)은 구성 단계에만 들어간다. 연구소는 구성 단계를 반복해 시험한다.
  - 일관성 계약을 정하는 단계가 위치 제안에서 구성으로 옮겨진다(ADR-0022 갱신).
  - 그림 형식은 경로(route, ADR-0025)로 고른다. 사람이 지정하지 않으면 구성이 제안할 수 있다.
  - 피드백을 어느 단계로 보낼지는 사람이 고른다. shortcut으로 표시한 AI 판정은 미루었다.
- 관련: ADR-0011, ADR-0017, ADR-0022, ADR-0023, ADR-0025, RES-009, LAB-001
