# ADR-0025 · 그림은 image·svg 두 경로 중 하나로 만들고, 결과는 공통 형식으로 받는다

- 맥락:
  - 위치 제안(`figure_plan`) → 사람 선택·방향(ADR-0023) → 생성 → 확인 흐름은 이미 있다. 생성 수단만 모든 유형에서 anatomy 아이소메트릭 SVG 하나로 고정되어 있다.
  - f1·f4 파일럿에서 그림 한 장에 약 25분, 1천만 토큰, 330KB가 들었고, 결과가 꾸밈에 그쳤다(RES-009 측정 기준).
  - 목록으로 충분한 자리(f1)도 후보에 남아 그림이 만들어졌다.
  - 시각화 팀은 본문을 바꾸지 않는다(FIGURE-001 본문 불변). "글로 둔다"는 생성 경로가 아니라 후보를 고르지 않는 것이다.
- 대안:
  - A. 현행 유지(모든 유형을 SVG 하나로 생성): 장면 유형의 비용과 꾸밈 문제가 남는다.
  - B. 지시문 안에서 모델이 도구를 고름: 선택 기준이 코드 밖에 있어 검증과 교체가 어렵다.
  - C. 유형별 경로 세 개(image·diagram·chart): diagram과 chart는 산출 형식·안전 검사·표시가 같아 경로 수준에서 나눌 이유가 없다.
  - D. 산출 형식으로 나눈 두 경로(image·svg)와 교체할 수 있는 어댑터. 유형별 차이는 svg 경로 안에서 다룬다. 선택하였다.
- 선택(D):
  - 필요성: 위치 제안은 후보마다 이 그림이 없으면 독자가 놓치는 것(`without`)을 적는다. 사람은 답이 약한 후보를 고르지 않는다. 본문 보강이 필요하면 초안작성팀에 요청으로만 남긴다.
  - 경로:
    - `image`: 장면·비유(`scene`). 이미지 생성 모델 어댑터(Higgsfield MCP 등)가 래스터 파일을 만든다.
    - `svg`: 그 밖의 유형. 내부 단계는 ADR-0024를 따른다.
    - 유형별 기본 경로는 코드의 표 하나에 두고, 사람이 후보마다 바꿀 수 있다.
  - 두 경로는 같은 구성 명세를 입력으로 받는다(RES-009 원칙 1). 구성은 좌표 없이 메시지 하나, 메시지를 이루는 요소, 영역, 움직일 대상을 적는다.
  - 경로의 차이는 능력(움직임, 그림 속 글자, 부분 편집)으로만 드러낸다. 상위 계층은 어댑터 이름을 분기하지 않는다.
  - 그림 속 글자는 어댑터 능력이다. 최근 이미지 모델이 한글을 그릴 수 있으므로 금지하지 않는다. 어댑터가 글자를 그리지 못하면 결과에 글자 층을 따로 담는다.
  - 그림끼리는 서로 모른 채 병렬로 생성하고, 반복 대상과 스타일은 ADR-0022 계약으로 맞춘다. 사람 확인은 ADR-0017처럼 한 장씩 한다.
  - 계약 상세(결과 형식, 어댑터 입출력, 검사, 호환)는 FIGURE-002가 원본이다.
- 이유:
  - 유형마다 맞는 수단이 다르다. 수량·구조는 좌표를 코드가 맡아야 정확하고(RES-009 원칙 2), 장면은 이미지 생성이 시간과 비용을 줄일 것으로 예상한다. 이 예상은 f4 비교 시험으로 확인한다.
  - 산출 형식 단위로 경로를 나누면 경로마다 안전 검사·표시·내보내기 방식이 하나씩 대응하고, 새 모델은 어댑터 하나만 추가하면 된다.
  - 능력 플래그로 차이를 드러내면 모델 성능이 바뀌어도 상위 계약을 고치지 않는다.
- 결과:
  - 현재 `figures[].svg` 단일 필드는 FIGURE-002의 결과 형식으로 넓힌다. 기존 SVG 결과는 svg 경로 결과로 읽는다.
  - 화면 표시, 내려받기, 내보내기(ADR-0012)는 파일 형식별로 처리한다.
  - 비교 시험은 f4(산길) 한 장으로 하며, 실제 생성은 사용자 허락 뒤에 한다(TIME-001). 그림 속 글자 기본값도 이 시험으로 정한다. 판정은 사람이 한다(JUDGE-001).
- 관련: RES-009, ADR-0012, ADR-0017, ADR-0022, ADR-0023, ADR-0024, FIGURE-001, FIGURE-002, JUDGE-001, TIME-001
