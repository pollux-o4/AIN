# ADR-0011 · 시각자료는 초안 확정 뒤 선택 단계로 두고 본문을 바꾸지 않고 배치한다

- 맥락: 글만으로 전하기 어려운 관계·순서·비교를 보여 줄 시각자료가 필요했다. 이를 필수 8단계에 넣으면 모든 글에 비용이 들고, 본문과 함께 작성하면 확정한 글이 다시 바뀐다.
- 대안:
  - 초고 단계에서 함께 생성하는 방안은 본문과 그림이 함께 바뀌고 매번 비용이 든다.
  - 발행 준비 승인 뒤에 추가하는 방안은 승인한 결과물과 전달하는 결과물이 달라진다.
  - 초안 확정과 발행 준비 승인 사이에 선택 단계를 두는 방안을 채택했다.
- 선택(2026-11-12 사용자 결정):
  - 흐름: 초안 확정 → [시각자료 추가 → 시각자료 확인] 또는 [시각자료 없이] → 발행 준비 승인 순서로 간다. 승인 대상은 본문과 확인한 시각자료(`approval.figures`)이다.
  - 본문 불변: 시각자료는 앵커 문장이 들어 있는 문단 뒤에만 배치하며, 초안 확정 상태는 유지한다. 글을 수정하려면 기존 수정 요청 절차를 따라야 하며, 이때는 초안 확정·시각자료·승인이 모두 무효가 되고 시각자료는 이력에만 남긴다.
  - 위치(ADR-0017이 대체함: 모든 단위를 검토해 제안하고 그림 한 장씩 생성한다): 개념 소개 문단(정의 → 비유 → 결과·한계)마다 마지막 문장 뒤에 배치한다. AI가 후보(앵커 문장과 개념·비유 대상·결과를 담은 주장)를 제안하면 코드가 본문과 글자 그대로 대조해 중복을 없애고 최대 6개까지 남긴다. 사람이 고른 후보만 생성하며, AI 호출은 제안 1회와 생성(층 수 3회)으로 이루어진다.
  - 인계: 글을 먼저 완성해야 그림 담당 AI가 글의 의도를 이어받을 수 있다. 그림 담당 AI에 글 설계(audience·value·outline)와 본문 전체를 전달하고, 후보마다 reason(이 지점에서 독자가 이해해야 할 내용), analogy(본문 비유 대상), scene(라벨 없이 보이는 원인 → 결과)을 함께 넘긴다. 그림을 그릴 때는 본문의 비유 대상을 분해해 그리며 다른 사물로 바꾸지 않는다.
  - 상태: AI가 처리할 때는 `waiting_figure`, 선택을 기다릴 때는 `awaiting_figure_choice`, 확인을 기다릴 때는 `awaiting_figure_review`를 쓴다. 사람이 확인하면 `satisfied`와 `figure.phase=confirmed` 상태가 된다. 준비 단계(후보와 생성물)와 사람 확인 단계는 서로 다른 상태와 기록으로 구분한다.
  - 형식:
    - SVG 단일 요소로 만든다.
    - 실행 요소, 외부 참조 요소, 외부 참조 속성과 함께 주소나 이벤트 속성을 바꾸는 애니메이션은 계약에서 거부한다.
    - 다만 SVG 자체 움직임(SMIL·`<style>` 안 @keyframes)은 기본 속성만으로 뜻이 통하고 `prefers-reduced-motion`에서 멈추는 경우에 한해 허용한다(2026-11-13). 생성 규칙은 ADR-0028이 정한다.
    - 스크립트 기반 상호작용과 WebGL은 생성하지 않는다.
    - 화면에서는 동일 출처 파일을 `<img>`로만 표시하며, 파일 응답에는 `default-src 'none'; sandbox`를 적용한다.
  - 생성(모델 배정과 일괄 생성은 ADR-0017이 대체한다):
    - `figure` 단계는 `/anatomy` 스킬을 기준으로 층을 나눈 AI 작업 3회로 진행한다(2026-11-13 사용자 결정, f1 교차 비교 근거). 다음 세 층을 차례로 거친다.
      - 초안(gemini-4-hydrogen-medium, 2026-11-14 Flash 3.8 대체): 구도와 비유 배치를 맡는다.
      - 내용 편집(gpt-6-luna high): 비유, 요소 대응, 인과, 사실 대조를 맡는다.
      - 시각 마감(claude-sonnet-5-5 medium): 정렬, 그리기 순서, 라벨, 강조 색, 움직임을 맡는다.
    - 위치 제안은 내용 담당 모델이 맡으며, 층별 모델은 `AIN_FIGURE_AI_<PLAN|DRAFT|CONTENT|VISUAL>`로 바꿀 수 있다.
    - 앞 층의 SVG는 작업 폴더 파일(`input-<id>.svg`)과 메모(`notes`)로 전달하고, 상태에는 `figure.pass`와 `figure.drafts`만 기록한다. 사람 확인은 마지막 층 뒤에 한 번만 한다.
    - 스킬은 provider 공통 원본 `~/.codex/skills`를 각 provider 경로(Claude `~/.claude/skills`, agy `~/.gemini/config/skills`)에 심링크로 연결한다. 이 단계에 한해 작업 폴더 안의 도구 사용을 허용하며, 스킬 불러오기에 실패하면 생성 실패로 처리한다. 다만 `figure_plan`에서는 도구 사용 금지를 유지한다.
    - 제한 시간은 층마다 60분으로 두며, 실행 한도는 층 수 × 60분이다.
    - SVG는 작업 폴더 파일로 출력하고 응답에는 절대 경로(`svgFile`)만 적는다. 어댑터는 AI 작업 루트 안의 파일만 읽어 같은 검사를 적용하되, 응답 앞의 확인용 메모와 첨부는 무시하고 마지막 결과 블록만 읽는다. 상한은 400,000자이다.
  - 검수 권한: ADR-0006과 같은 원칙(지시는 에이전트도, 결과물 수락은 사람만)을 따른다. 위치 제안 요청·위치와 스타일 선택·구성 승인·수정 요청은 에이전트도 할 수 있고, 확정·제외는 사람만 한다(에이전트 요청은 403). 동작별 권한은 `contracts/actions.mjs` 카탈로그 하나가 정한다.
- 책임:
  - 생성은 `automation/paseo/`(담당 illustrator·프롬프트·결과 계약)가 맡는다.
  - 전이는 `automation/n8n/`이 맡아 기존 전달·대기 루프를 유지하고 사람 결정에서 멈춘다.
  - 배치와 확인 상태 저장은 `automation/editorial/`(domain/figures)이 맡는다.
- 용어: 화면에서는 '시각자료'를, 코드와 계약에서는 `figure`를 사용한다.
- 비용: 상태 3개와 사람 결정 2회가 추가된다. 다만 시각자료를 사용하지 않는 글에는 변화가 없다.
- 관련: FLOW-002, EDIT-001, FIGURE-001, ADR-0006, ADR-0010, ADR-0012(내보내기)
