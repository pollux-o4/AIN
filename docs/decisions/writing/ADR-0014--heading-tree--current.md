# ADR-0014 · 소제목은 내용의 계층 구조를 따르는 안내로 구성한다

- 맥락: 구성이 `##` 구간 목록만 생성하여 대등한 하위 항목(예: 생각 방식 4묶음·7개 명칭)이 한 문단에 뭉치는 문제가 생겼다(392자 문단 실측). 또한 끝 정리 `### 한눈에 정리`가 마지막 구간의 하위 항목처럼 보였다.
- 역할:
  - 제목은 읽기 전 단계에서 글을 고르게 하고 전체 틀과 최상위 주제를 드러내며, 다시 찾을 때의 기준 명칭이 된다.
  - 소제목은 읽는 중에는 현재 위치·내용 구분·미리 보기 구실을 하고, 읽은 뒤에는 기억 단서와 재탐색 진입점이 된다.
  - 훑어보는 독자에게는 결론, 차례대로 읽는 독자에게는 궁금증, 다시 찾는 독자에게는 항목명이 필요하므로 단계마다 역할을 나눈다.
- 대안:
  - 깊이 상한을 두는 방안(`####` 금지 등)은 깊은 참조 글에서 하위 항목이 문단으로 합쳐져 재탐색 진입점이 사라진다.
  - 소제목 형식을 하나로 통일하는 방안은 한 형식이 세 가지 역할을 모두 맡기 어렵다.
  - 내용의 계층 구조와 단계별 역할을 함께 적용하는 방안을 채택했다.
- 선택: 내용의 계층 구조와 단계별 역할을 함께 적용한다.
  - 계층 깊이는 내용의 포함 관계를 따르며 상한을 두지 않는다. 깊이 대신 다음 네 가지를 기준으로 삼는다.
    - 같은 층위의 항목 수는 단계마다 3~5개를 목표로 한다.
    - 하위 항목을 1개만 두는 분할은 금지한다.
    - 계층 단계를 건너뛰지 않는다.
    - 같은 층위 항목의 명칭 형식은 통일한다.
  - `##` 구간 소제목은 그 구간에서 독자가 얻을 답을 짧고 자연스러운 말로 적되 정해진 문형을 두지 않는다(ADR-0019). 하위 소제목(`###` 이하)은 짧은 항목 명칭으로 적으며, 여는 질문은 소제목이 아니라 본문 첫 문장(hook)에 둔다.
  - 하위 항목이 있는 경우에는 상위 항목의 첫머리에서 아래 항목을 미리 안내한다.
  - 끝 정리는 본문 계층 구조 밖에 `## 한눈에 정리`로 둔다. 다만 구간 분할 작성에서는 기존 구간 예산과 기준본 동작을 유지하기 위해 마지막 구간에 포함한다.
- 구현:
  - 구간 카드의 `subsections`(재귀 구조)는 `contracts/ai-output`에, 소제목 줄 형식(`sectionHeading`·`subsectionHeading`·`summaryHeading`)은 `contracts/article-structure`에 정의한다.
  - 코드 지표는 `headingTree`(단계 건너뛰기·하위 항목 1개 분할·최대 같은 층위 항목 수, count)와 `missingHeadings`(하위 항목 포함, exact)로 산출한다.
  - 전체 구조가 드러나는지와 같은 층위 항목의 명칭 형식이 통일되었는지는 검토(S9)에서 판단한다(JUDGE-001).
- 검증 기준: 본문을 지우고 제목과 소제목만 남겼을 때 글의 약속(제목), 구조 안내(상위 단계), 다시 찾을 항목명(하위 단계)이 드러나는지를 확인한다.
- 관련: ADR-0009, ADR-0013, RES-007(S9)
