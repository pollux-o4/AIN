# ADR-0019 · 지시문은 자연스러운 한국어를 요구하고 문형을 정하지 않는다

- 맥락: 실제 글(알고리즘 입문, 2026-11-17)에 콜론 소제목, 'A가 아니라 B' 굵은 문장, '~하십시오' 마무리 문장, 지도·가로줄·세로줄·칸 비유가 반복되었다. 사용자는 이를 어색한 한국어이며 독자가 머리를 한 번 더 쓰게 만든다고 지적했다.
- 원인(근거): 모델의 기본 문체가 아니라 지시문이었다.
  - 항목 안내의 예시가 글에 그대로 실렸다(예: 소제목 안내의 '이름: 결론' 예시가 실제 소제목 형식이 되었다).
  - 항목마다 문형을 정했다(강조 문장은 'A가 아니라 B' 대비, 마무리 문장은 명령형, explain 글은 비유 대상 필수). 그 결과 모든 구간이 같은 틀로 작성되었다.
  - 지시문의 내부 은유(지도·이름표·칸)가 본문의 낱말로 그대로 유출되었다.
- 원칙: 글의 목적은 독자가 불필요한 사고 부담 없이 바로 이해하도록 하는 것이다. 지시문은 이 목적과 항목의 역할만 정하고 문장 형식은 정하지 않는다.
- 선택:
  - 공통 기준 `NATURAL_KOREAN`(`paseo/seasoning`): 소리 내어 읽어 자연스러운 한국어를 쓴다. 번역투, 문형에 끼워 맞춘 문장, 한 번 더 옮겨 생각해야 하는 추상 비유는 쓰지 않는다. 구성과 초고에 적용하고, 검토 S4 점검 항목에 포함한다. 제목처럼 독자에게 그대로 보이는 짧은 항목은 짧은 항목 규칙표의 안내와 점검 질문에도 같은 기준을 싣는다(ADR-0020). 실제 글(API 입문, 2026-11-24)의 제목 '한눈에 잡는'은 제목을 만드는 주제 단계에 이 기준이 없어 생긴 번역투였다.
  - 항목 안내(`contracts/ai-output`): 소제목은 독자가 얻을 답, 강조 문장은 기억하기 쉬운 일상어 1문장, 마무리 문장은 preserveVoice 말투의 판단·행동 1문장으로 정한다. 문형 지정과 본문에 실릴 수 있는 예시 문장은 두지 않는다.
  - 비유(`analogySystem`): 일상 사물이 개념과 직접 대응할 때만 둔다. 없으면 비유 없이 직접 설명한다(P4).
  - 지시문 낱말: 내부 은유 대신 글에 써도 되는 낱말(구조·명칭·항목·순서 개요)을 쓴다.
  - 구성 단계: 여러 구간의 같은 항목을 같은 문형으로 쓰지 않는다. 구간 카드의 여는 문장·마무리 문장 형태와 문단 구성은 ADR-0029가 정한다.
- 판정: 자연스러움은 검토(LLM) 점검표로만 본다. 코드는 문형·낱말을 검사하지 않는다(JUDGE-001).
- 대체: ADR-0014의 구간 소제목 문형(이름과 결론), RES-007 S7·S8 통과 기준의 문형 지정(대비 문장, 명령형)
- 관련: ADR-0013, RES-007, JUDGE-001, TERM-001
