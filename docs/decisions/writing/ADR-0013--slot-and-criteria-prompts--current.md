# ADR-0013 · 단계 프롬프트는 채울 항목과 통과 기준으로 작성한다

- 맥락: 단계 프롬프트가 규칙 문장 나열과 형용사 지시("쉽게 설명") 위주여서 결과 수준이 모델에 따라 달라졌다. 출력 예시는 `"string"` 자리표시자뿐이었고, 프롬프트 조립·시각자료·결과 파싱이 `prompts.mjs` 한 파일에 섞여 있었다. 또한 RES-007에서 S 기준 필수화 범위와 구간 카드 항목 구조 반영 여부가 정해지지 않은 상태였다.
- 대안:
  - 더 강한 모델로 고정하는 방안은 모델에 의존하게 된다.
  - 모범 글 예시를 첨부하는 방안은 RES-007에 따르면 효과가 적다.
  - 항목 안내·통과 기준·코드 검사를 함께 사용하는 방안을 채택했다.
- 선택:
  - 틀: 모든 과업 프롬프트는 `역할 → 이번 일 → 순서 → 규칙 → 통과 기준 → 출력 → 지킬 것 → <자료>` 순서로 구성한다. 첫 줄에는 `[과업 ID]`를 두고, 마지막 줄에는 출력 형식을 재확인하는 문구를 둔다. 통과 기준은 예 또는 아니오로 답할 수 있는 질문으로 작성한다.
  - 항목: 산출물 형식(`contracts/ai-output`)에 항목 안내를 함께 적고 프롬프트 예시가 이를 그대로 사용한다. 새로 추가하는 항목은 topic.titleCandidates, audience.scene, value.promise, research.cases, outline.title, review.checks와 구간 카드의 hook·cases·principleLine·underline이다.
  - 필수화: 구간 카드의 4개 항목은 procedure가 아닌 구간에서 코드가 검사한다(`domain/sections`). 빈 항목이면 1회 다시 작성하게 하고, 반복되면 `failed`로 처리한다(ADR-0009와 같은 경로). 나머지 새 항목은 이전 결과 파싱과 호환되도록 선택 항목으로 둔다.
  - 분량: 분량 요구가 있으면 구간 budget이 항목 내용을 전개할 최소 분량 이상인지 코드가 검사한다(`CARD_SPACE`, 구간 카드·도입부·끝 정리 몫 합산). 분량이 부족하면 구간 수를 줄이도록 1회 다시 요청한다. 다만 2개 구간으로도 최소 분량이 나오지 않는 짧은 글은 검사에서 제외한다.
  - 호출 예산: 코드 검사가 거부한 결과를 다시 작성하는 호출은 단계 예산에 포함하지 않는다(`continuesStage`. 횟수는 도메인 상한으로, 시간은 실행 시간 한도로 제한한다). 이는 구간별 초고의 다음 구간과 같은 규칙이다.
  - 문체: 글 전체의 말투(종결어미)와 시점은 진단 단계에서 하나로 정한다(diagnose.preserveVoice). 본문에 실릴 항목(scene·promise·구간 카드)과 초고·검토가 모두 같은 규칙을 따른다(`seasoning.VOICE`로 통일한다).
  - 초고: 구간 카드 항목을 정해진 순서대로 본문에 옮긴다. hook·underline·principleLine은 글자 그대로 옮기고, 글 끝 `### 한눈에 정리`에는 principleLine 목록을 적는다.
  - 검토: S1~S10 점검표(`checks`)를 사용한다. 구간 카드 항목 반영 여부와 제목 일치는 코드 지표 `draftMetrics.cardTransfer`만을 근거로 삼는다. revise 사유는 수정 해석 기준 미충족, 구간 카드 항목 반영 누락, S10 미통과로 한정한다.
  - 신뢰 경계: 자료는 `<자료>` 구역의 JSON 하나로 전달하며, 값 안의 닫는 표지는 이스케이프한다. 요구(idea·feedback·brief 등)와 재료(source·artifacts)를 구분하는 문구는 `GUARD` 한곳에 둔다.
  - 세션 재사용 턴: 역할·공통 경계·출력 공통 규칙은 첫 턴에만 넣고, 이후 턴에는 과업 내용과 바뀐 자료만 보낸다. 다만 신뢰 경계 한 줄과 기본값이 아닌 도구 규칙(시각자료 생성)은 매 턴 유지한다.
- 이유: 작문 교육 근거(RES-007 멱등성)에 따르면 절차와 완성물 목표를 명시하는 것이 효과적이다. 또한 셀 수 있는 것은 코드가 세어야 모델과 무관하게 일관성을 유지할 수 있으며(ADR-0007), 항목의 이름과 뜻이 산출물 형식과 같은 곳에 있어야 프롬프트와 파서가 어긋나지 않는다.
- 구조:
  - `paseo/prompts/`: frame(틀·읽기), stages(단계 정의), route, figure, index(조립)로 나눈다.
  - `paseo/results`: 응답을 이벤트로 변환한다.
  - `paseo/seasoning`: P·S 규칙과 점검표를 둔다.
  - `paseo/metrics`: 코드 지표를 산출한다.
- 결과: 구간 카드에 빈 항목이 있으면 구성 호출이 1회 늘 수 있고, 검토의 revise 사유가 많아져 자동 재작성(상한 2회, ADR-0007)도 더 자주 일어난다. 문자열 형식의 구간이나 항목이 없는 이전 구성은 검사와 대조에서 제외한다.
- 실측(실제 기본 모델, 합성 수필 600~900자):
  - 3개 구간(250·260·240자) 구성에서 첫 구간이 도입부와 구간 카드를 담지 못해 문장이 낱말 나열로 깨졌으며, 첫 구간을 1회 다시 쓰는 과정에서 8번째 호출을 소모해 검토 전에 한도로 멈췄다. 이는 위 분량 및 호출 예산 규칙의 근거가 되었다.
  - 2회차에서는 약속 문장은 합니다체, 본문은 한다체, 마무리 문장은 명령형으로 문체가 섞이고 도입 장면과 첫 사례가 같은 사건을 되풀이했다. 이는 문체 규칙 및 장면 중복 기준의 근거가 되었다.
- 평가: 한 번의 통과는 근거로 삼지 않는다. 서술 방식별 합성 글감 4건과 반복 실행을 조합해 기준별 통과율을 산출한다(`ai:eval`, `paseo/live/cases`, `grade`). 필수 기준은 코드가 세고 대조한 항목(분량·첫 회차 완료·구간 카드 항목·구간 카드 반영·소제목)과 검토 판정으로 두고, 점검표 항목별 미통과 횟수는 추세로 본다. 프롬프트나 모델을 바꿀 때는 전후 표로 비교한다.
- 판정 경계: 코드는 개수 세기와 글자 대조만 하고, 뜻을 읽어야 하는 기준은 검토 점검표가 판정한다(계약 JUDGE-001). 낱말 일치 지표(과장어·말투 어미·도입 표지·미풀이 용어·호칭 비율)는 오판의 근거가 되어 없앴다.
- 규칙 단일화: 과장어 예시 목록(`seasoning`)은 작성 규칙과 항목 통과 기준이 공유하며 코드는 이를 세지 않는다. 설명 글의 '도입에 정의' 규칙은 도입부 순서(약속 문장 → 장면 → 순서)와 충돌하여 정의를 해당 구간으로 옮겼다.
- 장면(2026-11-15 실측 반영):
  - 사례 항목에는 교훈 요약이 아니라 장면(주인공·시간·장소·행동 하나·눈에 보이는 결과)을 적는다.
  - 가상 사례가 여럿이면 한 인물이 이어서 겪는 장면으로 쓰며, 구간마다 새 인물을 등장시키지 않는다.
  - 가상임은 처음 나오는 자리에서 한 번만 밝힌다.
  - 도입부의 역할과 여는 방식은 ADR-0021이 정한다.
  - 구간은 세 문단(여는 질문과 장면 / 풀이와 강조 문장 / 마무리 문장)으로 구성하며, 여는 질문·장면·풀이·강조 문장·마무리 문장에서 같은 말을 되풀이하지 않는다.
  - 근거: "한 사용자가 … 위험해졌습니다"와 같은 요약 사례 때문에 한 구간에서 같은 말이 5~6번 반복되었다(RES-007 독자 불만 1위).
- 항목 길이: 여는 질문·강조 문장·마무리 문장의 글자 수 상한(짧은 항목 규칙표 `SLOT_RULES`, ADR-0020)을 구성 검사가 센다. 이는 60~80자에 이르는 강조 문장이 실리던 실측에 따른 것이다.
- 형식 내성: 선택 항목의 빈 문자열과 null은 없는 항목으로 읽는다(첫 구간 prerequisite의 빈 문자열 "" 때문에 구성 전체가 실패한 실측에 따른 것이다). 다만 필수 항목의 빈 값은 그대로 거부한다.
- 확인 범위: 장면 규칙 적용 뒤 실제 모델로 서술 방식별 1회씩 실행한 결과 수필·설명·주장은 끝까지 마쳤으나 따라 하기는 위 형식 문제로 마치지 못했다. 그 뒤의 수정(약속 문장 대조·가상 표시 인칭별 규칙·빈 항목 내성)은 실제 모델로 확인하지 못했다.
- 미결정:
  - 최소 분량 수치(어림값, 코드에 shortcut으로 표시)
  - 짧은 글용 구간 카드 축약
  - 과장어 사전과 도입부 표지 낱말의 근거(현재 최소 목록, 코드에 shortcut으로 표시)
  - 새 항목의 화면 노출
  - 실제 독자 검증(RES-007의 한계와 같다)
- 관련: RES-007, RES-002, RES-005, ADR-0007, ADR-0008, ADR-0009, FLOW-002
