# ADR-0013 · 단계 프롬프트는 채울 칸과 통과 기준으로 쓴다

- 맥락: 단계 프롬프트가 규칙 문장 나열·형용사 지시("쉽게 설명")라 결과 수준이 모델에 따라 갈림 · 출력 예시는 `"string"` 자리표시자뿐 · 조립·시각자료·결과 파싱이 `prompts.mjs` 한 파일에 섞임 · RES-007 미결정(S 기준 필수화 범위·카드 필드 스키마 반영)
- 대안: 더 강한 모델로 고정(모델 의존) / 모범 글 예시 첨부(RES-007: 효과 작음) / 칸·기준·코드 검사
- 선택
  - 틀: 모든 과업이 `역할 → 이번 일 → 순서 → 규칙 → 통과 기준 → 출력 → 지킬 것 → <자료>` 순서 · 첫 줄 `[과업 ID]` · 마지막 줄에 출력 형식 재확인 · 통과 기준은 예/아니오 질문
  - 칸: 산출물 형식(`contracts/ai-output`)에 칸 안내를 함께 적고 프롬프트 예시가 그대로 가져감 · 새 칸 topic.titleCandidates · audience.scene · value.promise · research.cases · outline.title · 구간 카드 hook·cases·principleLine·underline · review.checks
  - 필수화: 이야기 카드 4칸은 procedure가 아닌 카드 구간에서 코드가 검사(`domain/sections` · 빈 칸이면 1회 다시, 반복이면 `failed` · ADR-0009와 같은 경로) · 나머지 새 칸은 선택(이전 결과 파싱 호환)
  - 지면: 분량 요구가 있으면 구간 budget이 칸을 옮길 최소 지면 이상인지 코드가 검사(`CARD_SPACE` · 카드 구간·글머리·끝 정리 몫) · 모자라면 구간 수를 줄이게 1회 다시 · 2구간으로도 지면이 안 나오는 짧은 글은 검사 제외
  - 호출 예산: 코드 검사가 거부한 결과의 다시 쓰기는 단계 예산에 넣지 않음(`continuesStage` · 횟수는 도메인 상한, 시간은 실행 시간 한도) · 구간별 초고의 다음 구간과 같은 규칙
  - 말투: 글 전체의 말투(종결어미)·시점은 진단이 하나로 정함(diagnose.preserveVoice) · 본문에 실릴 칸(scene·promise·구간 카드)과 초고·검토가 같은 규칙을 따름(`seasoning.VOICE` 한곳)
  - 초고: 카드 칸을 정해진 순서로 옮김 · hook·underline·principleLine은 글자 그대로 · 글 끝 `### 한눈에 정리`에 principleLine 목록
  - 검토: S1~S10 점검표(`checks`) · 카드 옮김·제목 일치는 코드 지표 `draftMetrics.cardTransfer`만 근거 · revise 사유는 편집 메모 기준 미충족·카드 옮김 누락·S10 미통과로 한정
  - 신뢰 경계: 자료는 `<자료>` 구역의 JSON 하나 · 값 안의 닫는 표지는 이스케이프 · 요구(idea·feedback·brief 등)와 재료(source·artifacts) 구분 문구는 `GUARD` 한곳
  - 세션 재사용 턴: 역할·공통 경계·출력 공통 규칙은 첫 턴에만 싣고 이후 턴은 과업 내용·바뀐 자료만 보냄 · 신뢰 경계 한 줄과 기본값이 아닌 도구 규칙(시각자료 생성)은 매 턴 유지
- 이유: 작문 교육 근거(RES-007 멱등성)는 절차·완성물 목표의 명시가 효과 · 셀 수 있는 것은 코드가 세야 모델과 무관(ADR-0007) · 칸 이름·뜻이 형식과 같은 곳에 있어야 프롬프트와 파서가 어긋나지 않음
- 구조: `paseo/prompts/` frame(틀·읽기) · stages(단계 정의) · route · figure · index(조립) / `paseo/results`(응답 → 이벤트) / `paseo/seasoning`(P·S 규칙·점검표) / `paseo/metrics`(코드 지표)
- 결과: 구성 호출이 카드 빈 칸으로 1회 더 일어날 수 있음 · 검토 revise 사유가 늘어 자동 재작성(상한 2회, ADR-0007)이 더 자주 일어날 수 있음 · 문자열 구간·칸 없는 이전 구성은 검사·대조에서 제외
- 실측(실제 기본 모델 · 합성 수필 600~900자): 3구간 250·260·240자 구성에서 첫 구간이 글머리와 카드를 담지 못해 문장이 낱말 나열로 깨짐 · 첫 구간 다시 쓰기 1회가 8번째 호출을 써 검토 전에 한도로 멈춤 → 위 지면·호출 예산 규칙의 근거 · 2회차: 약속은 합니다체, 본문은 한다체, 닫는 줄은 명령형으로 섞이고 도입 장면과 첫 사례가 같은 사건을 되풀이 → 말투 규칙·장면 중복 기준의 근거
- 평가: 한 번의 통과는 근거가 아님 · 글감(서술 방식별 합성 4건) × 반복 실행으로 기준별 통과율을 냄(`ai:eval` · `paseo/live/cases`·`grade`) · 필수 기준은 코드가 세고 대조한 것(분량·첫 회차 완료·카드 칸·카드 옮김·소제목)과 검토 판정, 점검표 항목별 미통과 횟수는 추세 · 프롬프트·모델 변경은 전후 표로 비교
- 판정 경계: 코드는 세기·글자 대조만, 뜻을 읽어야 하는 기준은 검토 점검표가 판정 · 낱말 일치 지표(과장어·말투 어미·도입 표지·미풀이 용어·호칭 비율)는 오판 근거가 되어 제거 · 계약 JUDGE-001
- 규칙 단일화: 과장어 예시 목록(`seasoning`)은 규칙·칸 통과 기준이 공유(코드가 세지 않음) · 설명 글 '도입에 정의' 규칙은 글머리 순서(약속 → 장면 → 순서)와 충돌해 정의를 해당 구간으로 옮김
- 장면(2026-11-15 실측 반영): 사례 칸은 교훈 요약이 아니라 장면(주인공·때·곳·행동 하나·눈에 보이는 결과) · 지어낸 사례는 도입 장면의 주인공이 이어서 겪는 장면(구간마다 새 인물 금지) · 가상임은 글머리에서 한 번 · 글머리는 장면 → 약속·순서 · 구간은 문단 셋(질문과 장면 / 풀이와 밑줄 / 닫는 줄) · 질문·장면·풀이·밑줄·닫는 줄의 같은 말 되풀이 금지 · 근거: "한 사용자가 … 위험해졌습니다" 식 요약 사례 때문에 한 구간에서 같은 말이 5~6번 반복(RES-007 독자 불만 1위)
- 칸 길이: 질문·밑줄·닫는 줄의 글자 수 상한(규칙표 `SLOT_RULES`, ADR-0020)을 구성 검사가 셈 · 60~80자 밑줄 문장이 실리던 실측 · 약속 문장은 글머리에 글자 그대로 실렸는지 대조(`cardTransfer.promiseInLead`)
- 형식 내성: 선택 칸의 빈 문자열·null은 없는 칸으로 읽음(첫 구간 prerequisite ""로 구성 전체가 실패한 실측) · 필수 칸의 빈 값은 그대로 거부
- 확인 범위: 장면 규칙 적용 뒤 실제 모델 1회씩(수필·설명·주장 완료, 따라 하기는 위 형식 문제로 미완료) · 그 뒤의 수정(약속 대조·가상 표시 인칭별 규칙·빈 칸 내성)은 실제 모델 미확인
- 미결정: 최소 지면 수치(어림값, 코드에 shortcut) · 짧은 글용 카드 축약 · 과장어 사전·도입 표지 낱말의 근거(현재 최소 목록, 코드에 shortcut) · 새 칸의 화면 노출 · 실제 독자 검증(RES-007 한계 그대로)
- 관련: RES-007 · RES-002 · RES-005 · ADR-0007 · ADR-0008 · ADR-0009 · FLOW-002
