# ADR-0014 · 소제목은 내용의 나무를 따르는 지도

- 맥락: 구성이 `##` 구간 목록만 만들어 나란한 하위 항목(예: 생각 방식 4묶음·7개 이름)이 한 문단에 뭉침(392자 문단 실측) · 끝 정리 `### 한눈에 정리`가 마지막 구간의 하위 항목처럼 보임
- 역할: 제목 = 읽기 전(고르게 함·틀·나무의 뿌리·다시 찾는 이름) · 소제목 = 읽는 중(위치·덩어리·미리 보기)과 읽은 뒤(기억 고리·다시 들어오는 문) · 훑는 독자는 결론, 차례로 읽는 독자는 궁금증, 돌아오는 독자는 이름표가 필요 → 단계마다 역할을 나눔
- 대안: 깊이 상한(`####` 금지 등 · 깊은 참조 글에서 하위 항목이 문단으로 뭉개져 다시 찾는 문이 사라짐) / 소제목 형식 하나로 통일(세 역할을 한 형식이 못 맡음) / 내용 나무 + 단계별 역할
- 선택: 내용 나무 + 단계별 역할
  - 깊이는 내용의 포함 관계를 따름 · 상한 없음 · 제한 변수는 깊이가 아니라 단계당 형제 수(3~5 목표)·자식 1개 마디 금지·단계 건너뛰기 금지·형제 이름 모양 통일
  - `##` 구간: 이름표 + 결론 · 하위(`###` 이하): 짧은 이름표 · 질문은 소제목이 아니라 본문 첫 문장(hook)
  - 하위 마디가 있으면 부모 첫머리에서 아래 항목을 미리 보여 줌
  - 끝 정리는 본문 나무 밖: `## 한눈에 정리` · 분할에서는 마지막 구간에 붙음(구간 예산·기준본 동작 유지)
- 구현: 구성 카드 `subsections`(재귀) `contracts/ai-output` · 소제목 줄 형식 `contracts/article-structure`(`sectionHeading`·`subsectionHeading`·`summaryHeading`) · 코드 지표 `headingTree`(건너뛰기·자식 1개·최대 형제 수 = count)·`missingHeadings`(하위 마디 포함 = exact) · 지도가 그려지는지·형제 이름 모양은 검토(S9) · JUDGE-001
- 검증 기준: 본문을 지우고 제목·소제목만 남겨도 약속(제목)·지도(위 단계)·다시 찾을 칸 이름(아래 단계)이 보이는가
- 관련: ADR-0009 · ADR-0013 · RES-007(S9)
