# ADR-0020 · 짧은 항목 규칙을 규칙표 한 곳에서 정의한다

- 맥락:
  - 제목과 한 줄 항목의 규칙이 항목 안내(contracts/ai-output), 구성 기준(paseo/prompts/stages), 검토 점검표(paseo/seasoning CHECKS), 상한 값(SLOT_MAX)에 흩어져 있었다.
  - 한 곳만 고치면 나머지가 옛 규칙을 말했고, ADR-0019의 예시 유출도 같은 원인이었다.
  - 실제 글 10회차 제목은 39자 설명문("…알 수 있습니다")이었다.
- 원칙: 항목마다 역할, 근거, 셀 수 있는 상한을 한 번만 적는다. 쓰는 AI, 코드, 검토 AI가 모두 거기서 읽는다.
- 선택:
  - 규칙표 `contracts/slot-rules`의 `SLOT_RULES`에는 항목마다 role(역할 문장), max(공백 포함 글자 수), basis(근거)를 적는다.
  - 쓰는 AI는 `slotGuide`(role과 상한)를 항목 안내로 받는다.
  - 코드는 max만 센다. 구성 검사에서 max를 넘는 구간 한 줄 항목과 글 제목을 반려한다. 뜻은 판정하지 않는다(JUDGE-001).
  - 검토 AI와 구성 자기 점검은 `slotCheck`(같은 role 문장)를 점검 질문으로 받는다. S1에 제목 역할을 포함한다.
  - 제목은 독자가 글을 고를 때 읽는 짧은 문구다. 얻을 것을 쉬운 낱말로 적고, 본문 문장처럼 '…습니다'로 끝맺는 설명문은 금지한다. 상한은 25자다.
- 대안:
  - 제목 어미를 코드로 판정하는 대안은 낱말과 정규식 판정이라 JUDGE-001을 위반하고, '…하는 법' 같은 좋은 제목도 걸린다.
  - 항목마다 각 파일에 따로 적는 현행 방식은 어긋남이 다시 생긴다.
- 확장: 새 짧은 항목은 규칙표에 한 줄을 더하면 안내, 검사, 점검표에 함께 반영된다.
- 한계: 상한은 한국어 표본 근거가 없는 어림값이다. 명사구 제목과 문장형 제목을 직접 비교한 연구는 RES-007에 없다. 쉬운 단어와 짧은 제목의 근거는 Shulman 2024이다.
- 관련: ADR-0013, ADR-0019, RES-007, JUDGE-001
