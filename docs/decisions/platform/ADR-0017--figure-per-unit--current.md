# ADR-0017 · 시각자료는 글의 모든 단위를 훑어 제안하고 그림 한 장씩 생성

- 맥락: 사람은 시각 정보를 글보다 빨리 받아들이므로, 시각화할 수 있는 곳은 많을수록 좋다(2026-11-17 사용자 결정). 기존 설계에는 세 가지 제약이 있었다.
  - 위치 제안이 개념 소개 문단에만 한정되고 후보가 최대 6개였다.
  - 고른 그림 전부를 한 세션이 층마다 한꺼번에 생성해, 그림이 늘수록 맥락·제한 시간·실패 범위가 함께 커졌다.
  - 끝난 그림의 세션이 대기 상태로 남았다.
- 선택:
  - 위치 제안:
    - 코드가 글머리와 모든 소제목을 검토 단위(`units`)로 넘긴다.
    - AI는 단위마다 구조·순서·대비·분류·순환·수량·비유 장면을 찾아 대상마다 후보를 제안한다(`kind`: structure|flow|comparison|hierarchy|cycle|chart|table|scene).
    - 후보가 없는 단위는 `skipped`에 단위 이름과 이유를 적는다.
    - 안전 상한은 30개이고 id는 `FIGURE_ID`(f1~f99)를 따른다.
  - 개선 신호: 코드가 단위별 집계 `figure.coverage`를 센다(JUDGE-001 세기만).
    - 집계 항목: 단위 수, 후보가 놓인 단위, 건너뛴 단위, 빠진 단위, 후보 수.
    - 빠진 단위가 있거나, 단위가 3곳 이상인데 후보가 1개 이하이면 `figure_coverage_low` 기록을 남기고 화면에 표시한다. 이는 위치 제안을 고쳐야 할 근본 개선 신호이다.
  - 생성: 작업 단위는 그림 한 장이다(`figure.current = {id, pass}`).
    - 순서: f1 초안 → 내용 → 시각 → f2 …. 앞 층 결과는 `figure.draft`, 마친 그림은 `figure.items`에 둔다.
    - 사람 확인은 모두 마친 뒤 한 번 한다.
    - 실패하면 그 그림의 그 층만 다시 실행한다.
    - 호출 예산과 실행 한도는 남은 (그림 × 층) 수를 기준으로 한다.
  - 세션:
    - 담당 세션 열쇠는 `<담당>:<그림 id>`이다(`sessionKeyOf`).
    - 내용 편집 층은 그린 담당(`illustrator`)과 분리된 `figure_editor`가 맡는다. 작성과 검토를 분리하는 것과 같은 독립성이다.
    - 이어 맡을 작업이 없는 세션(내용 층, 시각 층 뒤)은 대기시키지 않고 바로 내려놓는다(`sessionEndsAfter`).
  - 모델: 위치 제안과 모든 생성 층에 Hydrogen 4 High를 쓴다(2026-11-17 사용자 결정). 층별 교체는 `AIN_FIGURE_AI_<PLAN|DRAFT|CONTENT|VISUAL>`로 유지한다.
- 결과:
  - 그림 수만큼 AI 호출이 늘어난다(그림 × 3). 사람이 후보를 골라 비용을 정한다.
  - 한 그림의 실패나 지연이 다른 그림에 번지지 않는다.
  - 그림 단위 진행 도입 전에 생성 중이던 상태는 첫 미완 그림의 첫 층부터 다시 실행한다.
- 대체: ADR-0011의 위치(개념 소개 문단·최대 6개)·생성(층 단위 일괄)·모델 배정 항목
- 관련: ADR-0011 · ADR-0015 · FIGURE-001 · JUDGE-001
