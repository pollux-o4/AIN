# ADR-0009 · 분량 예산이 있으면 초고를 구간별로 작성

- 맥락: 구성 예산(4,500자)·구간별 실측·삭감량을 줘도 초고 모델이 7~9천 자 작성 · 통째 재작성은 요청 제한 120초 초과로 실패 반복
- 대안: 더 강한 모델·긴 제한 시간(모델 의존) / 초고 후 일괄 잘라 맞춤(실패 재현) / 구간 단위 작성(지면 단위 원고)
- 선택: 분량 요구 또는 구간 budget이 있으면 outline 구간(2~8개)마다 별도 호출 · 구간 예산 125% 초과 시 그 구간만 다시(상한 3회 · 2회로는 2,089→1,930→1,810자로 좁혀지다 허용치 60자 앞에서 멈춘 실측, 소진 후에도 초과면 수용하지 않고 `failed` · 이어가기는 같은 지적으로 재개) · 순서대로 합쳐 draft 산출물 1개
- 구현: `domain/sections.mjs`(계획·수용·합치기) · nextAction에 `section` · 결과 이벤트 `section` 일치 검사 · 문맥은 직전 구간과 같은 순서의 이전 구간만
- 예산: 분량 요구가 있으면 outline 결과를 코드가 검사(2~8구간·모든 구간 `budget`·합계가 요구 범위 안) · 위반이면 1회 다시(`retryNote`), 반복이면 `failed` · 균등 배분 대체 경로 없음(예산 누락 구성이 1,650자×3으로 통과해 7천 자대 원고가 된 실측) · 이어지는 구간 호출은 단계 예산에서 제외(구간 수 상한으로 제한)
- 전체 분량과 묶기(2026-11-15): 구간 한도 = min(예산 125%, 전체 상한 − 이미 쓴 분량 − 남은 구간 예산) · 마지막 구간은 전체 하한을 채우는 최소 분량도 검사 · 구간마다 125%를 따로 허용하면 합계가 상한을 넘어 구성부터 다시 쓰던 실측(예산 780자 → 917자, 요구 600~900자, 호출 9 → 13~14회) · 구간 한도를 지킨 글은 전체 범위를 벗어나지 않음 → ADR-0007 분량 가드는 구성 뒤에 분량 요구가 바뀐 경우의 안전망으로 남음
- 구조(2026-11-15): 모든 구간이 `## 구간 제목`으로 시작(첫 구간은 제목·도입 뒤) · 글 분할의 단일 정의 `contracts/article-structure` · 첫 구간에 소제목이 없던 이전 초고도 기준본으로 읽음
- 글머리(2026-11-17): 원고(구간별이면 첫 구간)는 `# 구성 제목` 줄로 시작해야 수용 · 형식 대조만 · 어긋나면 반려 원고와 사유로 다시(한 번에 쓴 초고도 같음) · 구성 재작성 뒤 제목·글머리 없는 원고가 검토까지 간 실측
- 다시 쓰기: 거부된 구간 원고를 기준본으로 주고 줄이는 편집으로 요청 · 처음부터 다시 쓰면 2,556→2,470→2,262자로 거의 줄지 않은 실측 · 다시 쓰기 상태는 `state.retry` 하나
- 측정(2026-11-11): 분량은 독자에게 보이는 글자(공백 포함) · 마크다운 링크 주소 제외(참고 문헌 URL ~510자가 예산을 잠식) · 원천 `domain/length.mjs` `readerLength`
- 결과: 호출당 작업량이 작아 시간 초과 완화 · 초과를 구간 단위로 즉시 교정 · 분량 예산이 없는 글은 기존처럼 한 번에 작성(추가 비용 없음)
- 입력: 의뢰 시 분량 프리셋(짧게·보통·길게) 또는 CLI `--length` · 같은 ±10% 규칙 `lengthRange`
- 관련: ADR-0007 · ADR-0008 · RES-006
- 시간(2026-11-11): 구간 호출 실측 96~116초 · 출력 대부분이 사고 토큰 · 품질 위해 사고 단계 유지, 요청 상한 300초·전체 1,800초로 시간 수용 (OPS-003)
