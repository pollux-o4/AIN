# ADR-0010 · 수정 해석 승인 게이트 · 사람 수정 요청은 해석 확인 후 착수

- 맥락: ADR-0008 편집 메모가 해석 직후 바로 수정 루프 착수 · 잘못된 해석(예: "구성은 그대로"인데 구성부터 재작성)을 긴 초고 루프·비용 뒤에야 발견
- 근거: RES-006 실제 편집 협업 · 편집 메모(edit letter)를 저자와 합의한 뒤 작업
- 선택:
  - 상태 `awaiting_brief`: 사람 피드백 → route(편집 메모 제안) → 사람 확인 대기 · 산출물 불변(waiting_route와 같은 계약)
  - 사람 동작: `approve_brief`(그대로 또는 `edit{intent,target,priorities,preserve}`만 보정) → 승인 대상 단계부터 수정 · `revise_brief`(보정 의견을 피드백에 덧붙여 route 재요청)
  - 승인 이후 자동 보정(ADR-0007)은 승인된 메모 안에서 추가 승인 없이 진행
  - 편집장(에이전트) 수정 지시는 지시자가 해석을 확정(`briefPreapproved`) · 사람 지시의 해석 승인·재해석은 사람 또는 편집장 대리(2026-11-11 사용자 결정 · 편집장이 해석을 검토·확정해 진행 · 재해석은 수정 지시 한도에 포함)
  - 표시: 화면 "수정 해석 확인"(편집 가능 양식·가정 표시·"이대로 진행"/"고친 해석으로 진행"/"다시 해석") · CLI `approve-brief`·`revise-brief` · `can.approveBrief`
- 이유: 해석은 짧은 호출(약 15초)·초고 루프는 수 분·고비용 · 비용이 들기 전 의도 정렬 · 피드백 문구 해석을 과제별 규칙 없이 사람이 바로잡음
- 비용: 사람 피드백마다 확인 1회 증가
- 관련: ADR-0006 · ADR-0007 · ADR-0008 · FLOW-002 · RES-006 · e2e BRIEF-001
