# ADR-0015 · Paseo 세션 수명은 소유 표시와 주기 정리로 관리

- 맥락: 담당 재사용(대기 세션)과 검증 실행(`ai:test:contract`·`ai:eval`)이 세션을 남김 · 실측(2026-11-17) AIN 표시 세션 166개 중 158개가 끝난 검증 실행의 대기 담당 · 제공자 프로세스 130개 약 8.1GiB
- 원인: 대기 세션 해제가 "같은 글의 다음 단계가 가져감"에만 의존 · 사람 피드백 대기·실행 종료·런타임 종료 시 해제 경로 없음 · 세션에 소유 런타임 표시 없음
- 대안: 작업 끝마다 모두 보관(재사용 이득 상실) / 검증 실행에만 정리 추가(서비스 누적은 그대로) / 소유 표시 + 정책 기반 주기 정리
- 선택: 소유 표시 + 정책 기반 주기 정리 · 단일 정의 `paseo/lifecycle.mjs`
  - 표시: 모든 세션 `labels{source, owner(작업 저장소 절대 경로), job}`
  - 정책 `SESSION_POLICY`: 대기 담당 유휴 15분 · 총량 6개(오래 쉰 것부터 해제) · 막 끝난 세션 2분 유예(결과 회수 전)
  - 정리 대상: 진행 중 작업·남길 대기 담당이 아닌 내 세션 · 주인 경로가 사라진 세션 · 표시 없는 이전 세션(내 작업 폴더 밖)
  - 시점: 서비스 60초 주기 · 서비스 종료·검증 실행 종료 시 대기 담당까지 전부(`all`) · 수동 `mise run ai:prune`
- 결과: 세션 수가 진행 중 작업 + 대기 상한으로 묶임 · 대기 해제 뒤 다음 단계는 새 세션(첫 턴 전체 전송)
- 제약: 표시 없는 이전 세션은 내 작업 폴더 밖이면 주인 없음으로 봄 → 이 변경 전 코드로 동시에 돌고 있는 검증 실행이 있으면 그 대기 담당도 정리됨
- 관련: ADR-0013(담당 재사용)
