# ADR-0007 · 코드 판정 요구사항은 상태 머신 가드로 강제

- 맥락: 분량 요구(4,500자)가 글감 문장에만 있고 전이 조건이 아님 · review 결과와 무관하게 `awaiting_user` · 수정 2회 후에도 8,363자
- 대안: 검토 AI 지적에 의존 / 편집장(ADR-0006)이 매번 되돌림 / 상태 머신 가드
- 선택: review 완료 시 `requirements.mjs` 검사 → 미충족이면 회차를 열고 검사가 지정한 단계부터 재작성(분량: 1차 outline 예산 재배정, 이후 draft를 구간별 실제 글자 수·삭감량과 함께 잘라 맞춤 · 모델이 예산을 60% 넘게 초과한 실측 근거) · 상한 `AUTO_CORRECTION_LIMIT`(2) · 소진 시 `awaiting_user` + `unmet` · 코드 판정 미충족(분량 등)이 남으면 `satisfy` 거부(`blockingUnmet`) · 검토 판정(`kind: review`)은 주관이라 사람 판단으로 승인 가능
- 이유: 결정적 판정·테스트 고정 · AI 피드백 생성이 아니라 코드 규칙이므로 FLOW-002 "AI 자체 피드백 금지"와 양립 · 상한·회차 예산으로 무한 반복 차단
- 요구 원천: 요구 장부(ADR-0016)로 대체 · 자동 보정 지시문은 장부에 쓰지 않음
- 결과: 자동 회차마다 새 실행 예산 · 이벤트 `auto_correction` · 사람·편집장 피드백은 보정 횟수 초기화 · 프롬프트에 `requirements` 전달(구성은 글자 예산 배정)
- 확장: `CHECKS`에 종류별 검사기 추가(target·evaluate) · 값은 장부가 줌 · 여러 미충족이면 가장 앞 단계로
- 갱신(2026-11-11): 상한 소진 후 7,460자 원고가 만족 승인 가능 상태로 통과한 실측 → 승인 차단 추가 · 해소는 사람 피드백(새 요구·새 회차)
- 관련: FLOW-002 · ADR-0006 · RES-005
