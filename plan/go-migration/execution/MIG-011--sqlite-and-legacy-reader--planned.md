# MIG-011 · SQLite 저장과 호환 읽기

선행 MIG-001 계약. 전용 경로 `backend/internal/store/`. 기준은 `EditorialStore`, `JobStore`, `workers`와 MIG-003의 합성 기존 데이터다.

1. 현행 `editorial_runs(id, request_id, value)`를 읽고 새 작업 선점·원격 연결·결과 적용 기록은 별도 테이블로 둔다. 기존 작업 파일은 어댑터에서 읽어 작업 ID와 원격 ID를 연결한다. 스키마 버전 및 재실행 가능한 추가 마이그레이션을 작성한다.
2. 요청 ID·operation ID·글 버전·작업 키의 유일성 및 조건부 쓰기를 저장 포트로 노출한다. 작업 예약과 예산 반영, 완료 적용과 선점 해제는 각각 같은 트랜잭션 안에서 처리한다. 외부 I/O는 트랜잭션 밖에서 수행한다.
3. 목록은 필요한 필드만 조회하고 대기 조회는 페이지 또는 스트림으로 소비한다. WAL, busy 처리, 경로·파일 권한을 확인한다. 같은 DB의 쓰기 경쟁과 누락 필드의 왕복을 검증한다.

완료 기준: 두 동시 선점 중 하나만 성공하며 동일 결과가 두 번 반영되지 않는다. DB를 닫고 다시 열면 작업과 원격 참조를 복원한다. 기존 큰 행·과거 회차·보관 상태·이력을 읽고 알 수 없는 필드를 보존한다. 배리어와 임시 DB로 검사한다.

최소 실행: `go -C backend test ./internal/store/...`와 경합·해제 사례의 `go -C backend test -race ./internal/store/...`. 명령은 해당 패키지 구현 후 사용한다.

검증: AIN-API-001, EDIT-001, HISTORY-001.
