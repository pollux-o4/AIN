# MIG-052 · Go 조립·통합 검증

선행 MIG-001~003, MIG-011~014, MIG-021~025, MIG-031~033. 성능 비교에는 MIG-051을 사용한다. 이 작업의 전용 범위는 `backend/cmd/ain/`, `backend/internal/runtime/`, `tests/migration/integration/`, 브라우저 설정, 공용 빌드·검증 설정이다. 변경량 때문에 주 작업자가 부여한 통합 과업 한 건으로 개별 머지를 조립하고, 교차 수정은 담당자에게 돌려보낸다.

1. Go 서버에서 저장·편집·실행·Paseo·HTTP·UI 자산을 조립한다. 프로젝트가 자신의 Go 서버만 기동·종료하도록 하고 공용 Paseo는 외부에 둔다. 기존 기동·종료·상태 확인 명령에 후보 런타임을 연결한다.
2. 합성 제공자에서 작성→검토→수정→시각자료→사용자 승인→TXT/내보내기·인계를 끝까지 확인한다. 각 단계의 중복 요청, 연결 유실, 취소, 강제 중지 뒤 재시작, 동시 글의 상태 격리, 하위 그림 상한을 통합에서 대표 사례 한 번씩 재현한다.
3. Playwright PC·모바일, CLI, 레거시 DB fixture를 Go 진입점에 연결한다. 평상시 fixture 검증에는 실제 모델을 호출하지 않는다. `go test -race` 범위와 fixture 흐름을 기존 검증 예산에 배치하고 TIME-001을 준수한다.
4. 성능 목표와 합성 부하 반복에서 제한·복구를 확인한다. 실제 agy 확인이 필요하면 사용자 실행 또는 명시적 요청을 받은 별도 `AIN_LIVE=1` 검증에 필요한 명령과 증거 범위를 준비한다. 합성 검증과 실제 데몬·모델 검증 결과를 구분한다.

완료 기준: 기존 주요 여정의 차이가 전부 해소됐거나 승인된 명세 변경에 연결된다. 사용 진입점에서 Go 후보가 동작하고 변경 범위의 PC·모바일 E2E와 통합 검증이 각각 시간 예산 안에서 통과한다. 전체 검증은 MIG-054 최종 트리에서 수행한다. Paseo 직접 연결과 전송 확인/중단 의미에 차단이 있으면 운영 전환을 보류한다.

검증: AIN-API-001, FLOW-001, FIGURE-001, LIVE-001, AGENT-001, ARCH-001, TIME-001.
