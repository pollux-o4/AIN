# MIG-054 · MIT 배포와 n8n 기본 경로 제거

선행 MIG-052와 MIG-053의 합성 이관·복구 통과. 운영 로컬 적용은 해당 이관 마일스톤에서 승인한다. 전용 범위는 릴리스 패키징과 문서이며, 실행 설정과 코드 제거는 통합 담당과 순서대로 인계한다.

1. Go 서버와 빌드된 React 자산으로 패키지를 만든다. Node·n8n이 없는 환경에서 서버가 기동하고 로컬 UI와 상태 조회가 동작하는지 확인한다. TS CLI의 Node 요구사항, 별도 공통 Paseo 설치·인증을 운영 안내에 반영한다.
2. 기본 mise 설치·기동·검증에서 n8n과 Node 서버 의존을 제거한다. 실제 모델 검증, 연구소·평가·가지치기 도구의 n8n 또는 JS SDK 의존을 전수 확인해 실행 계약이나 합성 시험을 이식한다. 유지할 기준 Node 코드가 필요하면 고정 기준 커밋에서 재현한다.
3. AIN 자체 코드의 MIT 라이선스 문구와 저작권자, Go 의존성·UI 글꼴·프런트 자산·이식한 프로토콜 소스의 재배포 고지를 확인한다. 제3자 의존성의 라이선스와 고지를 보존하고 n8n 배포물을 패키지에서 제외한다.
4. 새 ADR의 current 전환과 대체 ADR의 stale 처리를 한 변경으로 적용한다. AIN-API-001·LIVE-001·ARCH-001·TOOL-001·TIME-001은 ID를 유지해 갱신한다. C2·C3 실행 경계, OPS-001·OPS-003·README·AGENTS의 진입점, OPS-002의 보존 의미와 최신 사용 가능 여부를 정리한다.

완료 기준: 클린 환경에서 배포본을 기동하고 UI·Go API와 CLI 호환을 확인한다. 배포 파일에 토큰·원문·운영 DB·n8n이 없고, 라이선스와 고지가 확인된다. 변경한 명세 ID에 대응하는 테스트와 적용 후 운영 절차를 검색할 수 있다. 통합 담당이 최종 트리에서 `mise run verify -- --force`를 한 번 실행해 300초 및 작업별 예산을 확인하고, 주 작업자가 결과를 승인한다.

검증: AIN-API-001, AGENT-001, ARCH-001, TOOL-001, TIME-001, OPS-001, OPS-003.
