# MIG-053 · 운영 이관과 복구

선행 MIG-011과 MIG-052. 전용 경로 `backend/tools/migrate/` 및 새 이관·복구 절차 문서. 합성 DB를 쓰는 도구 구현·복구 연습은 MIG-011의 데이터 계약 확정 후 착수할 수 있다. 운영 데이터 교체는 별도 이관 작업으로 승인된 뒤 수행한다.

1. 글·원고 회차·승인·과거 실행·보관·작업 ID·세션 연결·사용량·outbox의 목록과 대응 규칙을 만든다. 기존 `jobs/*.json`에서 job ID를 다시 계산하지 않고 기존 식별자와 원격 연결을 가져온다.
2. 활성 작업을 확인하고 정상 종료 후 Node/n8n의 쓰기를 차단한다. DB·WAL과 작업·결과·비공개 자격증명을 권한이 보호된 위치에 백업하고, 복제본에 Go 스키마를 적용한다. 모호한 원격 작업은 재실행 없이 확인 대기로 분류한다.
3. 레코드 수, ID, 상태와 회차·승인·이력·원고 바이트, 산출물 해시, 참조 무결성을 검증한다. 운영 전환은 단일 DB 작성자 원칙을 지키고 준비된 Go 런타임에 읽기 확인부터 한다.
4. Go 쓰기 허용 전에는 검증된 Node 백업으로 복구한다. Go 쓰기 후에는 Go에서 발생한 변경을 보존하는 역이관이 검증된 경우에만 Node 복귀를 허용한다. 그 외에는 Go 쓰기를 중지하고 최신 데이터 복제본에서 복구한다.

완료 기준: 합성 데이터에서 이관·재실행·중간 실패·복구를 모두 재현한다. 승인된 운영 이관에서는 검증된 복구본과 전환 확인 결과를 남긴다. 기존 n8n 실행 기록은 비공개 이력으로 보존한다.

검증: AIN-API-001, HISTORY-001, OPS-001, OPS-003.
