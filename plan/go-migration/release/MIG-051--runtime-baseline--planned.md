# MIG-051 · 상주 메모리와 실행 지연 기준선

선행 없음. 전용 경로 `tests/migration/perf/`. 독립 포트·합성 제공자·임시 DB를 쓴다.

1. 기존 Node+n8n에서 준비 직후 유휴, 글 1건, 동시 4건과 그림 묶음, 작업 종료·대기 세션 정리 후를 잰다. 큰 이력으로 목록 조회와 시작 시 복구도 잰다. 같은 fixture·호스트·로그 수준에서 Go 후보를 반복 측정할 실행기를 만든다.
2. 프로세스별 RSS와 가능한 경우 PSS, 전체 상주 메모리, goroutine·구독·실행/유휴 세션 수를 수집한다. AIN+n8n, 공통 Paseo, agy를 구분한다. 합성 제공자 결과와 실제 제공자의 과거 세션 정리 측정(ADR-0015)은 따로 표기한다.
3. 시간을 `완료 신호 → 상태 확인 → DB 저장 → API 관측`으로 나누어 p50·p95를 잰다. 편집기의 브라우저 반영 시간은 별도 측정으로 남긴다. Go 병목 분석을 위한 heap·goroutine 프로필은 로컬 진단에서만 사용한다.

완료 기준: 합성 비교 명령과 호스트/데이터 크기/동시성/반복 횟수를 남긴다. 초안 목표는 동시 4건에서 완료 신호부터 DB 반영까지 p95 250ms 이하, AIN 유휴 메모리 Node+n8n 기준 50% 이하, 반복 실행 종료 후 세션·구독 수가 정책 상한으로 복귀하는 것이다. 이 값은 계획 목표다. 기준선 측정 후 같은 부하에서의 비교 기준을 성능 명세에서 확정한다. 실제 agy를 포함하는 측정은 별도 승인을 받아 진행한다.

검증: TIME-001, ADR-0015. 성능 측정은 단위 테스트의 시간 경합 조건으로 사용하지 않는다.
