# AIN 글쓰기 대행

사용자 대신 AIN을 조작할 때에는 계약 AGENT-001에 따라 `mise run ain -- <명령>`을 사용한다. 화면(/write/)은 사용자가 진행 상황을 보고 싶다고 할 때에만 브라우저로 연다.

## 준비

- `mise run ain -- list` 실행 시 연결 오류가 발생하면 `mise run editorial:start`로 기동해도 되는지 사용자에게 묻는다. 상태는 `mise run editorial:status`로 확인한다.

## 의뢰

1. 대화에서 글감, 원하는 결과, 독자, 글 성격을 정리한다. 모호하면 한 번에 묻고, 정할 근거가 없으면 `auto`로 둔다.
   - mode는 explain(설명), procedure(따라 하기), argue(주장), narrate(이야기), auto 가운데 선택한다.
   - level은 beginner, intermediate, expert, auto 가운데 선택한다.
2. 사용자가 준 원문과 확인한 사실은 파일로 저장해 `--source-file`로 넘긴다. 링크만으로는 원문을 읽지 않는다.
3. `new`는 AI 비용이 발생하므로 정리한 의뢰 내용을 보여 주고 승인을 받은 뒤 실행한다.
4. `wait <id>`는 백그라운드로 실행하고 종료 시 결과를 확인한다. 폴링하지 않는다.

## 편집장 (ADR-0006)

AIN 내부에서는 수정 해석, 합격 판정, 분량 제한 검사를 기준으로 먼저 자동 수정 과정을 거친다(ADR-0008). 에이전트는 그 뒤 결과를 확인하고 추가 지시를 내리는 조언자 역할을 한다. 결과의 `brief`(수정 해석)가 의도와 다르면 그 차이부터 바로잡는다. 최종 검수(만족·발행 승인)는 사람만 한다.
사용자가 수정을 요청하면 `status`가 `awaiting_brief`(수정 해석 확인 대기)에서 멈춘다. 에이전트는 `brief`를 원래 요구와 피드백에 대조하여 검토한다(ADR-0010). 의도에 맞으면 `approve-brief`로 착수하고, 어긋나면 `revise-brief <보정 의견>`을 실행한다. 판단 근거는 사용자에게 짧게 보고한다.

- 위임 범위: 의뢰 시 사용자에게 수정 상한을 확인한다(기본·서버 상한 2회). 위임 범위 안의 `feedback`은 매회 승인을 받지 않는다.
- 판정 근거: 사용자 요구(분량·독자·목적)를 기준으로 `show --text` 본문, review `findings`, `history`를 대조하여 판정한다. 수치는 AIN 코드 지표만 인용하며 추정하지 않는다.
- 되돌림 조건: 요구 위반(분량 ±20% 범위 이탈, 독자 수준·목적 이탈), 사실 오류나 근거 없는 단정, 구조 문제(도입부의 요약과 전체 구조 안내 누락, 한 구간 안에 여러 개념이 섞인 경우)가 있으면 수정을 요청한다. 다만 문체 취향으로는 되돌리지 않는다.
- 지시 작성: 모든 문제를 위치(구간·표현), 바꿀 방향, 유지할 것으로 구분하여 한 번에 적는다. 같은 지적이 두 번 해결되지 않으면 중단하고 보고한다.
- 사용자 확인 요청: 되돌림 조건이 없거나 수정 상한(409)에 도달하면 사용자에게 판정 요약과 남은 문제를 보고하고 만족 여부를 묻는다.

## 결과 보고

- `status`, `label`, `issue`, `findings`를 근거로 실제 상태만 보고한다. AI 검토 통과를 만족이나 발행 승인으로 표현하지 않는다.
- 본문은 요약하여 전달하고, 전문은 요청 시 `show <id> --text` 또는 `download`로 제공한다. 그림이 포함된 결과는 `export <id> --format html|zip --out <파일>`로 내보내며, 확인된 시각자료만 포함한다.
- `issue`가 있으면 내용과 가능한 동작(`can`)을 알려 주고 사용자 결정을 받는다.

## 후속 동작

| 사용자 의도 | 명령 | 확인 |
| --- | --- | --- |
| 수정 요청 | `feedback <id> <구체적 수정 내용>` | AI 비용이 발생하며 수정 내용을 확인한 뒤 실행한다(편집장 위임 범위 안은 생략한다). |
| 일시 중지 요청 | `pause <id>` | 즉시 실행한다. |
| 시각자료 만들기 | `request-figures` → `select-figures <id> --input '{"figures":[...],"look":"manual"}'` → `approve-design` | AI 비용이 발생한다. 확정·제외는 사람이 화면에서 한다. |
| 작업 재개 요청 | `resume <id>` | AI 비용이 발생한다. |
| 보완 필요 표시 | `complete-requirements <id>` | AI 비용이 발생한다. |
| 결과 확정 | 사용자가 화면에서 확정 | 에이전트 요청은 서버가 403을 반환한다. |
| 발행 준비 승인 | 사용자가 화면에서 승인 | 에이전트 요청은 서버가 403을 반환한다. |
| 삭제 요청 | `delete <id>` | 제목을 보여 주고 확인을 받으며, 진행 중이면 먼저 `pause`한다. |

- 409 응답은 다른 경로에서 상태가 변경되었음을 뜻하므로 `show`로 최신 상태를 확인한 뒤 다시 판단한다.
- 실제 발행은 AIN 범위 밖이다.
